## 2. 摘要

### 2.1 摘要原文

Hand-Object Interaction (HOI) remains a core challenge in digital human video synthesis, where models must generate physically plausible contact and preserve object identity across frames. Although recent HOI reenactment approaches have achieved progress, they are typically trained and evaluated in-domain and fail to generalize to complex, in-the-wild scenarios. In contrast, all-in-one video editing models exhibit broader robustness but still struggle with HOI-specific issues such as inconsistent object appearance. In this paper, we present GenHOI, a lightweight augmentation to pretrained video generation models that injects reference-object information in a temporally balanced and spatially selective manner. For temporal balancing, we propose Head-Sliding RoPE, which assigns head-specific temporal offsets to reference tokens, distributing their influence evenly across frames and mitigating the temporal decay of 3D RoPE to improve long-range object consistency. For spatial selectivity, we design a two-level spatial attention gate that concentrates object-conditioned attention on HOI regions and adaptively scales its strength, preserving background realism while enhancing interaction fidelity. Extensive qualitative and quantitative evaluations on unseen, in-the-wild scenes demonstrate that GenHOI significantly outperforms state-of-the-art HOI reenactment and all-in-one video editing competitors. Project Page: https://xuanhuang0.github.io/GenHOI/.

### 2.2 摘要翻译

手-物交互（Hand-Object Interaction, HOI）仍然是数字人视频合成中的一项核心挑战，因为模型既要生成物理上合理的接触，又要在各帧之间保持对象身份一致。尽管近期的 HOI 重演方法已经取得进展，但它们通常在同一领域内训练和评测，难以泛化到复杂的真实野外场景。相比之下，一体化视频编辑模型表现出更强的鲁棒性，但仍然难以解决 HOI 特有的问题，例如对象外观不一致。本文提出 GenHOI：一种面向预训练视频生成模型的轻量级增强方法，以时间均衡且空间选择性的方式注入参考对象信息。为了实现时间均衡，作者提出 Head-Sliding RoPE，为参考 token 分配与注意力头相关的时间偏移，使其影响更均匀地分布到各个视频帧，并缓解 3D RoPE 的时间衰减，从而提升长时对象一致性。为了实现空间选择性，作者设计了一个两级空间注意力门，既把对象条件注意力集中在 HOI 区域，又自适应地调节其强度，在增强交互保真度的同时保持背景真实感。在未见过的真实野外场景上进行的大量定性和定量评估表明，GenHOI 显著优于当前先进的 HOI 重演方法和一体化视频编辑竞争方法。项目主页：https://xuanhuang0.github.io/GenHOI/。

## 3. 方法动机

### 3.1 作者为什么提出这个方法？

HOI 重演同时要求模型解决两个相互牵制的问题：一方面，手与新对象之间必须形成自然、符合动作语境的接触；另一方面，对象的颜色、纹理、形状和 logo 必须在长序列中保持稳定。专用 HOI 方法往往依赖领域数据与任务先验，在未见场景上泛化不足；大规模预训练的一体化视频编辑模型泛化更好，却容易让参考对象随时间变形或消失。作者希望保留基础视频生成模型已有的通用生成能力，只增加一个小比例参数的条件注入模块，把参考对象信息送到“正确的时间”和“正确的空间”。

### 3.2 现有方法的痛点或不足是什么？

第一，仅依赖编辑后的首帧会产生时间衰减：参考对象对早期帧影响较强，对后期帧影响较弱，长视频中容易逐步丢失对象细节。第二，把参考图直接粘贴到每帧掩码框中的 `ref-in-bbox` 条件虽然能维持外观，却诱导模型把任务当作简单复制粘贴，削弱对手-物接触和交互动态的建模。第三，无差别地让参考 token 影响所有视频 token 会污染背景；背景本来已经由未遮挡的参考视频充分约束，额外对象信息可能引入伪影。第四，专用分支或大规模结构改造会增加训练成本，也可能破坏预训练模型的通用能力。

### 3.3 论文的核心假设或直觉是什么？

参考对象 token 不应固定在一个远离后续帧的时间坐标上，而应让不同注意力头分别把它们“对齐”到不同时间位置，从多头整体上均衡覆盖视频时轴；与此同时，对象信息只需流向 HOI 区域，并应根据 token 内容自适应控制注入强度。时间均衡负责“每一段都记得对象是谁”，空间选择负责“只在需要交互的地方使用对象信息”。

## 4. 方法设计

### 4.1 整体 Pipeline

1. **构造训练条件。** 从原视频 $\mathbf{V}$ 中提取参考对象图 $I_{\mathrm{ref}}$，生成覆盖手-物区域的掩码视频 $\mathbf{V}_{\mathrm{mask}}$，并用常数填充后续帧掩码区域，得到参考视频 $\mathbf{V}_{\mathrm{r}}$。首帧保留完整内容，提供人物、场景和对象尺度的起始锚点。
2. **进入潜空间。** 预训练 VAE 编码器 $\mathcal{E}$ 分别编码参考视频和参考对象图；掩码经平均池化 $\psi$ 对齐潜空间分辨率。噪声视频 latent、参考视频 latent 和掩码沿通道维拼接，形成 DiT 的视频输入 token。
3. **注入对象 token。** 参考对象图生成独立的参考 token。在 DiT 自注意力中，Head-Sliding RoPE 为不同注意力头赋予不同的参考时间坐标，使这些 token 对整段视频的影响在头维度上近似均衡。
4. **限制注入位置与强度。** Hard Mask Gate 禁止参考对象信息流向背景 query，并禁止参考 query 反向读取视频 key；Soft Flow Gate 再根据更新后视频 token 的内容产生逐 token sigmoid 系数，调节对象条件的实际响应强度。
5. **去噪与解码。** DiT 在上述条件下迭代去噪，VAE 解码器生成视频。训练采用自监督重建目标；推理时把训练中的原对象图换成新对象图。可选的 First-Last-Frame（FLF）条件用首末边界帧进一步锚定长序列。

### 4.2 关键模块

#### 模块 1：HOI Condition Unit（HCU）

* 模块输入：噪声目标视频 latent $\mathbf{X}_t$、由掩码后源视频编码得到的 $\mathcal{E}(\mathbf{V}_{\mathrm{r}})$、下采样掩码 $\psi(\mathbf{V}_{\mathrm{mask}})$。
* 模块处理过程：首帧保留原视频，后续帧把 HOI 区域替换为归一化后为零的常数；随后将噪声 latent、参考视频 latent 与掩码沿通道维拼接，沿用基础 DiT 原有的输入组织方式完成条件化。
* 模块输出：包含生成目标、背景上下文和编辑区域指示的联合视频 latent $\mathbf{L}_v$。
* 模块作用：把通用图生视频模型改写为首帧条件的视频修复模型，让网络知道保留哪里、重绘哪里。
* 为什么需要该模块：它显式提供未遮挡背景与 HOI 区域边界，并避免增加一条完整控制分支；这有利于保留基础模型的泛化能力。
* 如果没有该模块会怎样：模型缺少稳定背景上下文和明确编辑区域，只靠参考对象 token 很难同时完成对象替换、背景保持和手部接触生成。Table 2 中 HCU 是全部消融的基础配置，但论文未单独给出“完全没有 HCU”的数值。

#### 模块 2：Head-Sliding RoPE

* 模块输入：参考对象 token 与视频 token 的多头注意力 query/key、latent 视频总帧数 $N_f$、注意力头数 $N_{head}$。
* 模块处理过程：标准 3D RoPE 分别编码时间、高度和宽度。视频 token 使用真实帧坐标；参考 token 的空间坐标仍与视频空间区分，但其时间坐标随注意力头编号 $n_{head}$ 变化，大致取 $\left\lceil N_f n_{head}/N_{head}\right\rceil$。不同头因此让参考 token 对齐到视频时轴的不同位置。
* 模块输出：经过头相关时空旋转编码的参考与视频 query/key。
* 模块作用：在多头聚合意义上，把对象参考响应摊到整个视频时轴，缓解固定参考坐标导致的后期响应衰减。
* 为什么需要该模块：RoPE 的相对位置距离会影响注意力响应；若所有参考 token 固定在帧坐标 $-1$，它们离后期视频帧越来越远，长视频更容易丢失对象身份。
* 如果没有该模块会怎样：仅使用 separate RoPE 时，Table 2 的 PSNR 为 29.73 dB、FVD 为 223.8；加入 Head-Sliding RoPE 后分别达到 30.88 dB 与 103.9，说明固定坐标尤其损害时序质量。论文将这一改善归因于时间响应均衡，但没有直接给出各帧注意力衰减曲线，因此“均衡”机制主要由设计逻辑和最终性能间接支持。

#### 模块 3：Hard Mask Gate（HMG）

* 模块输入：HOI 区域视频 token $T_{V_{HOI}}$、背景视频 token $T_{V_B}$、参考对象 token $T_{ref}$，以及它们的 $Q,K,V$。
* 模块处理过程：构造二值注意力掩码 $M$。背景 query 到参考 key 的通路被置零；参考 query 到所有视频 key 的通路也被置零；HOI query 仍可读取视频与参考 key。Figure 4 的注意力图显示，背景 query 对参考 key 的响应被屏蔽，HOI query 对参考 key 保持明显激活。
* 模块输出：只允许目标方向信息流的 masked self-attention 结果。
* 模块作用：控制对象信息“流向哪里”，把条件容量集中到手-物区域，并保护背景不被参考对象纹理污染。
* 为什么需要该模块：背景已经由 $\mathbf{V}_{\mathrm{r}}$ 提供充分上下文；重复注入对象信息没有收益，反而可能造成背景伪影。
* 如果没有该模块会怎样：对象 token 可以影响背景 query，模型更容易在非交互区域生成纹理污染；同时无法强制 HOI query 优先利用参考对象信息。消融把 HMG 与 Soft Flow Gate 合并为 SAG 整体评估，未分别报告 HMG 的独立数值贡献。

#### 模块 4：Soft Flow Gate（SFG）

* 模块输入：masked attention 更新后的视频 token $T'_v$。
* 模块处理过程：先对 token 做 LayerNorm，再经全连接网络 $\mathcal{F}$ 和 sigmoid 得到逐 token 门值 $G_v$，最后用逐元素乘法得到 $\tilde{T}_v=G_v\odot T'_v$。
* 模块输出：按内容自适应缩放后的更新视频 token $\tilde{T}_v$。
* 模块作用：控制对象信息“注入多强”，放大有效交互响应并抑制冗余响应，与 HMG 的离散空间约束互补。
* 为什么需要该模块：同一 HOI 掩码内不同位置、不同时间的条件需求并不相同，单纯的硬开关无法表达连续强度变化。
* 如果没有该模块会怎样：所有允许通行的对象响应只能以未调节的强度进入视频 token，可能造成过度条件化或不足条件化。论文未把 SFG 从 HMG 中单独拆出消融，因此这一点属于结构动机支持的合理推断，不能当作独立实验结论。

#### 模块 5：First-Last-Frame（FLF）边界条件

* 模块输入：编辑后的首帧和末帧，以及视频生成所需的其余条件。
* 模块处理过程：用序列两端的图像条件锚定生成轨迹。论文说明推理中的编辑首帧主要提供对象尺度线索；对象纹理主要来自参考图和 Head-Sliding 注入。
* 模块输出：边界约束更强的长视频生成条件。
* 模块作用：帮助模型在长序列中维持整体质量和边界一致性。
* 为什么需要该模块：只有首帧时，生成轨迹的远端约束较弱；增加末帧能减少长视频漂移。
* 如果没有该模块会怎样：Table 2 中 HCU + HS RoPE + SAG 的 PSNR/FID/FVD/OC 为 31.21/16.79/98.09/0.920，加入 FLF 后为 31.71/11.53/67.95/0.937。代价是结果依赖首末帧编辑的物理合理性；补充材料明确指出，短时间内不自然的手势过渡会损害视频质量。

### 4.3 关键公式或算法

#### 公式 1：条件视频重建目标

* 完整公式：$$\mathbf{V}=\mathcal{D}\!\left(\mathcal{M}\!\left(\mathbf{X}_{\mathrm{rand}},\mathcal{E}(I_{\mathrm{ref}}),\mathcal{E}(\mathbf{V}_{\mathrm{r}}),\psi(\mathbf{V}_{\mathrm{mask}})\right)\right)$$
* 变量含义：$\mathbf{V}$ 是目标原视频；$\mathbf{X}_{\mathrm{rand}}$ 是随机噪声；$I_{\mathrm{ref}}$ 是对象参考图；$\mathbf{V}_{\mathrm{r}}$ 是掩码后的参考视频；$\mathbf{V}_{\mathrm{mask}}$ 是 HOI 掩码；$\mathcal{E},\mathcal{D}$ 是预训练 VAE 编码器和解码器；$\mathcal{M}$ 是 DiT 去噪器；$\psi$ 是平均池化。
* 公式中每个部分的含义：编码器把图像/视频条件压缩到潜空间，池化后的掩码指示编辑位置，DiT 从噪声逐步恢复目标 latent，解码器把结果还原为视频。
* 公式整体的含义：训练任务是在遮挡背景、对象参考和掩码条件下自监督重建原视频。
* 公式目的：把无需成对“替换前-替换后”标注的训练数据转化为条件视频修复监督。
* 在方法流程中的作用：它统领 HCU、参考 token 注入和最终去噪输出，是训练信息流的总表达。
* 通俗理解：先把原视频里的手和物体盖住，再给模型一张物体照片和未遮挡背景，让它从噪声中把原视频还原出来；学会后即可把照片换成新物体。

#### 公式 2：掩码参考视频构造

* 完整公式：$$\mathbf{V}_{\mathrm{r}}=\begin{cases}\mathbf{V},&F=0,\\(1-\mathbf{V}_{\mathrm{mask}})\odot\mathbf{V}+\mathbf{V}_{\mathrm{mask}}\odot\lambda,&F>0,\end{cases}$$
* 变量含义：$F$ 在原文中表示帧索引；$\lambda=127$，归一化后为 0；$\odot$ 表示逐元素乘法。
* 公式中每个部分的含义：首帧完整保留；后续帧的非掩码区域保留原像素，掩码区域替换为常数。
* 公式整体的含义：生成一个“首帧完整、后续帧只挖去 HOI 区域”的参考视频。
* 公式目的：同时提供背景上下文、首帧锚点和明确的待生成区域。
* 在方法流程中的作用：这是 HCU 的原始视觉条件，之后经 VAE 编码并与噪声和掩码拼接。
* 通俗理解：保留场景和人物，只把后续帧中需要换物体的区域涂灰，让模型只重画那一块。

#### 公式 3：HCU 潜变量拼接

* 完整公式：$$\mathbf{L}_v=\operatorname{Concat}\!\left(\mathbf{X}_t,\mathcal{E}(\mathbf{V}_{\mathrm{r}}),\psi(\mathbf{V}_{\mathrm{mask}})\right)$$
* 变量含义：$\mathbf{X}_t$ 是扩散/流匹配过程在时刻 $t$ 的噪声目标视频 latent；其余符号同上。
* 公式中每个部分的含义：$\mathbf{X}_t$ 表示当前要去噪的内容，$\mathcal{E}(\mathbf{V}_{\mathrm{r}})$ 提供可保留区域，$\psi(\mathbf{V}_{\mathrm{mask}})$ 提供编辑位置。
* 公式整体的含义：三种互补信息沿通道维组合成 DiT 的视频输入。
* 公式目的：复用基础模型输入层，以较小结构改动引入 HOI 条件。
* 在方法流程中的作用：它把像素空间的修复问题转换成 DiT 可处理的潜空间条件生成问题。
* 通俗理解：给模型同时递三张“地图”：当前噪声、可复制的背景、需要重画的区域。

#### 公式 4：Head-Sliding RoPE 的时间坐标

* 完整公式：$$R_f=\begin{bmatrix}\left(e^{j\left\lceil\frac{N_f}{N_{head}}n_{head}\right\rceil\theta}\right)_{N\times D_1}\\\left(e^{jf^i\theta}\right)_{i=0}^{M-1}\end{bmatrix}$$
* 变量含义：$N$ 和 $M$ 分别是参考 token 与视频 token 数；$D_1$ 是 RoPE 中分配给时间维的通道数；$N_f$ 是 latent 视频帧数；$N_{head}$ 是注意力头数；$n_{head}$ 是当前头编号；$f^i$ 是第 $i$ 个视频 token 的帧坐标；$\theta$ 是 RoPE 频率；$j$ 是虚数单位。
* 公式中每个部分的含义：上半部分给同一注意力头中的所有参考 token 分配一个随头编号滑动的时间相位；下半部分保留视频 token 的真实时间相位。
* 公式整体的含义：不同头把参考图“放到”不同时间位置，所有头合起来覆盖整个序列。
* 公式目的：缩短参考 token 与不同视频帧之间的有效位置距离，缓解固定 $-1$ 坐标带来的远帧衰减。
* 在方法流程中的作用：它在 Q/K 进入自注意力点积之前改变旋转相位，从位置编码层面调整参考-视频注意力。
* 通俗理解：让不同注意力头分别负责视频的前段、中段和后段，避免所有头都只盯着开头的参考信息。

#### 公式 5：Hard Mask Gate

* 完整公式：$$M_{m,n}=\begin{cases}0,&m\in Q_{V_B},\ n\in K_{ref},\\0,&m\in Q_{ref},\ n\in\{K_{V_{HOI}},K_{V_B}\},\\1,&\text{其他情况。}\end{cases}$$ $$T_{out}=\operatorname{softmax}\!\left(\frac{M\odot QK^{\top}}{\sqrt{d_k}}\right)V$$
* 变量含义：$m,n$ 是 query/key token 索引；$V_B$、$V_{HOI}$ 和 $ref$ 分别表示背景、HOI 与参考对象 token；$d_k$ 是 key 维度。
* 公式中每个部分的含义：第一条屏蔽背景 query 读取对象 key；第二条屏蔽对象 query 读取视频 key；其余连接保留。掩码后的注意力分数经缩放、softmax，再对 value 加权。
* 公式整体的含义：对象信息可以进入 HOI 视频 token，但不能污染背景；参考对象 token 自身也不会被视频内容反向改写。
* 公式目的：建立有方向的参考信息流，集中 HOI 建模能力。
* 在方法流程中的作用：它位于自注意力分数计算阶段，是 Spatial Attention Gate 的离散空间约束。
* 通俗理解：给注意力连线设置交通规则：物体照片只准影响手和物体所在区域，不准跑到墙面、衣服或其他背景中。

#### 公式 6：Soft Flow Gate

* 完整公式：$$G_v=\sigma\!\left(\mathcal{F}(\mathcal{LN}(T'_v))\right),\qquad\tilde{T}_v=G_v\odot T'_v$$
* 变量含义：$T'_v$ 是 masked attention 更新后的视频 token；$\mathcal{LN}$ 是 LayerNorm；$\mathcal{F}$ 是全连接网络；$\sigma$ 是 sigmoid；$G_v$ 是逐 token 门值；$\tilde{T}_v$ 是最终门控视频 token。
* 公式中每个部分的含义：归一化稳定特征尺度，全连接层预测门控 logit，sigmoid 把系数限制在 0 到 1，逐元素乘法完成响应缩放。
* 公式整体的含义：模型根据每个 token 的内容决定保留多少更新信息。
* 公式目的：在硬空间掩码之外提供连续的条件强度控制。
* 在方法流程中的作用：它接在 masked attention 输出之后，是 Spatial Attention Gate 的软门控阶段。
* 通俗理解：Hard Mask Gate 决定哪些水管能通，Soft Flow Gate 再调节每根水管的流量。

#### 公式 7：Ref-in-bbox 对照策略

* 完整公式：$$\mathbf{V}_{\mathrm{r}}=\begin{cases}\mathbf{V},&F=0,\\(1-\mathbf{V}_{\mathrm{mask}})\odot\mathbf{V}+\mathbf{V}_{\mathrm{mask}}\odot\mathbf{I}_{\mathrm{ref}},&F>0.\end{cases}$$
* 变量含义：$\mathbf{I}_{\mathrm{ref}}$ 是被直接粘贴到掩码区域的参考对象图，其余符号同公式 2。
* 公式中每个部分的含义：首帧保留，后续帧非掩码区域复制源视频，掩码区域直接填入参考图像。
* 公式整体的含义：每一帧都显式展示目标对象外观，以维持跨帧一致性。
* 公式目的：这是作者用于说明 Head-Sliding 设计必要性的强对照条件注入方式。
* 在方法流程中的作用：它不是 GenHOI 最终方案，而是 Table 2 和 Figure 3 中的替代基线。
* 通俗理解：它相当于先把商品图片贴进每一帧，再让模型修边；商品更不容易忘，但手可能只是在图片旁边，交互不自然。

## 5. 与现有方法对比

GenHOI 的本质差异在于：它不依赖逐帧 warp 或强任务先验来传播对象，也不把参考图无差别地作为通用编辑条件；它在预训练 DiT 的 token 级自注意力中同时解决时间覆盖与空间路由。HCU 提供修复式输入组织，Head-Sliding RoPE 调整参考 token 的时间位置，SAG 约束参考信息的空间方向和强度。这样能在较少新增参数下利用大模型先验，但仍依赖掩码与参考图质量。

| 方法 | 核心思想 | 优点 | 缺点 | 改进点 |
|---|---|---|---|---|
| HOI-Swap | 图像级 HOI 修复结合顺序帧 warp | 针对对象替换设计，任务定义直接 | 依赖时序传播与领域数据；论文实验证明其在 AnchorCrafter_HOI 野外场景上的泛化和长时一致性较弱 | GenHOI 改用预训练视频 DiT，并通过 token 级条件注入直接建模整段视频 |
| Re-HOLD / ref-in-bbox | 用布局或边框把参考对象放入待修复区域 | 对对象外观有强显式约束 | 容易把任务退化为复制粘贴，手-物接触可能不自然；GenHOI 主表未直接评测 Re-HOLD | Head-Sliding 保留参考外观，同时让模型在 latent attention 中生成交互 |
| UniAnimate-DiT、MimicMotion | 首帧人物外观加姿态序列驱动的人体动画 | 人体运动控制成熟 | 原本并非 HOI 替换模型，需要适配；对象身份与接触不是核心约束 | GenHOI 用 HOI 掩码和对象 token 显式建模对象替换与接触区域 |
| VACE | 大规模预训练的一体化视频创建与编辑 | 泛化能力强、任务覆盖广，是论文最强通用基线 | HOI 特定对象一致性不足，尤其长视频后期会漂移 | GenHOI 在 Wan-14B-I2V 上增加时间均衡和空间选择注入，Table 1 的所有报告指标均优于 VACE |
| GenHOI | HCU + Head-Sliding RoPE + Hard/Soft Spatial Attention Gate + 可选 FLF | 对象一致性、HOI 自然度和野外泛化兼顾；仅增加 157M 参数 | 仍依赖 HOI 掩码、参考视角先验和首末帧物理合理性；复杂非刚体结果有采样方差 | 将参考条件的时间坐标、空间路由和强度控制显式解耦 |

## 6. 实验表现与优势

### 6.1 实验设置

基础模型为预训练 Wan-14B-I2V。训练集约含 19,000 段视频，使用 16 张 NVIDIA H100 80 GB GPU 训练 3 天，学习率为 $1\times10^{-5}$。论文称训练阶段从原视频抽取参考对象图和首帧，推理阶段由用户提供参考图，首帧由图像编辑模型生成。新增可学习参数为 157M，约占原 16.5B 参数模型的 0.95%。论文未明确报告优化器、batch size、随机种子、训练视频来源与许可、掩码生成器的完整配置，也未给出 3 天训练的总 GPU 小时之外的能耗或推理速度。

评测分为短视频 81 帧与长视频 401 帧。Self-reenactment 使用同一视频中提取的对象图重建原视频，有 ground truth；Cross-reenactment 用未在原序列出现的新对象替换原对象，没有成对 ground truth，因此使用分布指标和用户研究。所有需要首帧的方法在 cross-reenactment 中使用相同编辑首帧。用户研究包含 30 名参与者，评估 40 个短视频和 20 个长视频，以 1-5 分评价 Reference Fidelity（RF）与 Video Quality（VQ），论文称研究经 IRB 批准。

### 6.2 数据集

评测使用 AnchorCrafter 数据集中的野外人物重演视频。作者筛选分辨率至少为 720p 的视频，重组为 AnchorCrafter_HOI：50 段用于 self-reenactment，50 段用于 cross-reenactment。论文叙述强调这些是未见场景，但 camera-ready 正文中“该子集仅用于评测、不参与训练”的句子位于注释版本；摘要和正文仍多次宣称未见场景。由于论文未公开 19,000 段训练视频的详细组成，读者无法从现有材料独立排除内容重合或近重复，这属于证据边界，不等于已经发生数据泄漏。

补充材料没有增加定量数据集，只展示 AnchorCrafter 之外的额外案例，包括可变形物体、动态物理、复杂交互、遮挡、旋转、单视图/多视图参考和首帧编辑鲁棒性。

### 6.3 Baseline

主表包含四类基线：一体化视频编辑模型 VACE；人体动画模型 UniAnimate-DiT 与 MimicMotion；HOI 专用模型 HOI-Swap。Cross-reenactment 时对需要初始帧的模型提供相同编辑首帧。论文还在消融中比较 separate RoPE（Stand In 与 OminiControl 使用的独立坐标编码思想）和 Re-HOLD 风格的 ref-in-bbox。主表没有包含 Re-HOLD 的完整模型结果，也没有对论文仓库后续发布的 GenHOI-VACE 分支进行同表比较。

### 6.4 评价指标

Self-reenactment 使用 PSNR、SSIM、LPIPS 衡量逐帧重建保真度，使用 FID、FVD 衡量图像/视频分布质量，并使用 Object CLIP（OC）计算对象边框内生成内容与 ground truth 的 CLIP 相似度。PSNR、SSIM、OC 越高越好；LPIPS、FID、FVD 越低越好。Cross-reenactment 没有 ground truth，只使用 FID、FVD 和用户研究。用户研究的 VQ 与 RF 越高越好。

这些指标互补但仍有缺口：对象框内 CLIP 相似度不直接度量手指接触是否物理合理；FID/FVD 在只有 50 段测试视频的设置下可能对抽样敏感；用户研究正文没有报告置信区间、显著性检验、方法呈现顺序、盲法或每位参与者观看的具体分配。

### 6.5 主实验结果

**短视频 self-reenactment：** GenHOI 达到 PSNR 31.71、SSIM 0.952、LPIPS 0.036、FID 11.53、FVD 67.95、OC 0.937。相对最强通用基线 VACE（28.60/0.937/0.056/34.83/211.2/0.880），PSNR 提高 3.11 dB，LPIPS 降低 0.020，FID 降低 23.30，FVD 降低 143.25，OC 提高 0.057。

**短视频 cross-reenactment 与用户研究：** GenHOI 的 FID/FVD 为 58.83/429.5，VACE 为 68.67/524.7；对应改善为 FID 9.84、FVD 95.2。GenHOI 的 VQ/RF 为 4.487/4.636，VACE 为 3.942/2.796，尤其 RF 提高 1.840 分，支持对象参考保真度是主要优势。

**长视频 self-reenactment：** GenHOI 为 PSNR 30.69、SSIM 0.951、LPIPS 0.037、FID 9.78、FVD 42.17、OC 0.932；VACE 为 26.32、0.937、0.054、40.83、195.9、0.882。PSNR 优势扩大到 4.37 dB，OC 提高 0.050，表明视频变长后对象一致性优势仍然保留。

**长视频 cross-reenactment 与用户研究：** GenHOI 的 FID/FVD 为 57.62/515.0，VACE 为 81.77/782.0，FVD 改善 267.0；VQ/RF 为 4.458/4.534，VACE 为 3.143/2.287。长视频 VQ 差距约 1.315 分，比短视频约 0.545 分更大，符合 Head-Sliding 主要缓解长时衰减的设计目标。

Table 1 中 GenHOI 在全部报告指标上都是最佳值。该结论严格限于作者筛选的 AnchorCrafter_HOI、给定基线实现和当前评测协议；论文未报告多次训练或生成的均值与标准差，不能据此判断优势对随机种子和采样波动的稳定程度。

### 6.6 消融实验

消融在 AnchorCrafter_HOI self-reenactment 设置上进行。HCU 基线为 PSNR 28.25、SSIM 0.942、LPIPS 0.058、FID 22.89、FVD 248.6、OC 0.907。HCU + separate RoPE 为 29.73/0.945/0.050/22.66/223.8/0.908。HCU + ref-in-bbox 为 30.34/0.945/0.044/18.23/101.9/0.919。HCU + HS RoPE 为 30.88/0.951/0.039/17.92/103.9/0.915；相对 separate RoPE，PSNR 提高 1.15 dB，FVD 大幅降低 119.9；相对 ref-in-bbox，PSNR 提高 0.54 dB，但 FVD 略高 2.0、OC 略低 0.004，因此“所有指标都提升”的宽泛表述并不准确。

加入完整 SAG 后，结果为 31.21/0.952/0.038/16.79/98.09/0.920；再加入 FLF 后为 31.71/0.952/0.036/11.53/67.95/0.937。SAG 相对 HS RoPE 提高 PSNR 0.33 dB、降低 FID 1.13、降低 FVD 5.81、提高 OC 0.005；FLF 进一步提高 PSNR 0.50 dB、降低 FID 5.26、降低 FVD 30.14、提高 OC 0.017。

需要注意一处 camera-ready 文本错误：Table 2 的 HCU + HS RoPE + SAG PSNR 是 **31.21 dB**，正文写成从 30.88 提升到 **31.12 dB**。本阅读稿以最终表格 31.21 为准。另一个证据缺口是作者只对 SAG 整体做消融，没有分别拆除 Hard Mask Gate 和 Soft Flow Gate，因此两级门各自的独立贡献无法从现有表格确定。

### 6.7 可视化或定性结果

Figure 1 展示 VACE 与 GenHOI 的跨帧对比：VACE 中商品外观和局部纹理在时间上漂移，GenHOI 更稳定。Figure 3 比较三种参考注入方式：只有 HCU 时对象随时间退化；ref-in-bbox 保持外观但更像粘贴；作者方案兼顾对象一致性与接触自然度。Figure 4 可视化 HMG 后的注意力矩阵，背景 query 到参考 key 的区域为零，HOI query 对参考 key 有较强响应，与掩码设计一致。Figure 5 展示对口红、奶茶杯、玩具枪、爆米花桶等不同大小和类别对象的替换，以及相对 VACE、UniAnimate-DiT、MimicMotion、HOI-Swap 的结果。

补充材料 Figure 1 展示可变形袋装物、火花棒、吉他、遮挡和对象旋转。单视图参考在未见视角下能维持类别和大体几何，但 Figure 1(i) 的背面纹理与原对象不一致；多视图输入 Figure 1(j) 可改善纹理一致性。Figure 2 表明即使没有编辑首帧，模型也能依靠参考图生成合理结果；首帧姿态或位置有偏移时，最终视频仍有一定鲁棒性。作者还指出粗掩码与精确掩码都能工作，但掩码至少要覆盖原 HOI 区域，且更大掩码会引起更多内容变化。

这些图像支持“可处理多种对象和若干困难条件”的存在性结论，不能单独证明所有野外场景都稳定。补充材料也直接给出失败边界：未见视角的纹理由生成先验补全，复杂操作和非刚体对象在不同采样之间质量会波动。

### 6.8 局限性

论文明确报告两类限制。第一，FLF 模式依赖首末帧的物理合理性；现有图像编辑器难以保证短时间内手势从首帧自然过渡到末帧。第二，复杂操控或非刚体对象具有固有歧义，不同采样运行的质量可能不稳定。

结合方法和实验还能得到几项受证据支持的边界：单参考图无法观察对象背面，未见视角纹理依赖基础模型先验；HOI 掩码至少要覆盖原交互区域，因而上游掩码错误仍会传播；训练数据来源与去重信息不完整，未见场景泛化难以独立审计；主评测只有筛选后的 50 个 self 与 50 个 cross 视频，外部有效性仍需更多对象类别、动作、肤色、遮挡程度和拍摄域验证；没有报告运行时间、显存、推理吞吐、随机种子方差或统计显著性；用户研究协议信息不足以完整复现。HMG 中使用 $M\odot QK^\top$ 且以 0 表示禁止连接，从数学形式看，被屏蔽 logit 在 softmax 前变为 0，并不必然得到零概率；论文文字与 Figure 4 声称响应为零，实际实现可能还使用负无穷屏蔽，但论文公式和现有正文未明确说明这一实现细节，复现时必须核对代码。

## 7. 学习与应用

### 7.1 是否开源

已开源。官方 GitHub 仓库提供 Wan2.1 基础版本、GenHOI-VACE 分支、环境说明、权重和 demo/evaluation 数据目录示例。项目页也公开了视频结果。复现时应记录具体分支和 commit，因为仓库当前推荐的 VACE 分支是论文发表后的增强实现，可能与 camera-ready Table 1 的 Wan-14B-I2V 配置不同。

### 7.2 复现关键步骤

1. 准备 Wan2.1-I2V-14B 基础模型、GenHOI 对应权重和仓库指定依赖；根据目标选择论文主实验对应的 `main` 分支或后续 `vace` 分支。
2. 为源视频生成覆盖原手-物交互区域的 mask video，并准备目标对象参考图；可选地用图像编辑器生成首帧或首末帧。
3. 构造 HCU 输入：保留首帧，遮挡后续帧 HOI 区域，编码参考视频/对象图并下采样掩码，将噪声、参考视频 latent 与掩码通道拼接。
4. 在 DiT 自注意力中实现 Head-Sliding RoPE 和两级 SAG，确保 mask 语义与实现一致；加载 157M 额外参数或对应完整权重。
5. 按仓库命令生成 81 帧或 401 帧视频；self-reenactment 计算 PSNR、SSIM、LPIPS、FID、FVD、OC，cross-reenactment 计算 FID/FVD 并设计盲化用户研究。

如果从头训练，论文报告需要约 19,000 段视频、16 张 H100 80 GB、3 天和 $10^{-5}$ 学习率。现有论文没有公开足以完全复现训练的全部数据来源和超参数，因此最现实的路线是先用公开权重复现实验，再逐项核对训练脚本默认值。

### 7.3 需要注意的实现细节

* 公式 2 中 $\lambda=127$ 在论文的归一化方案下变为 0；若代码采用不同像素范围，不能机械照搬 127。
* $F$ 在公式的分支条件中被称为帧索引，同时前文也用 $F$ 表示总帧数，符号有复用；实现时应明确 `frame_idx == 0` 与 `num_frames`。
* Head-Sliding 的头编号起点（0-based 或 1-based）、上取整、latent 时间压缩后的 $N_f$ 和多头分组方式会影响实际坐标覆盖，必须以代码为准。
* HMG 若要让禁止连接的 softmax 概率严格为零，通常应把对应 logit 设为 $-\infty$ 或在 softmax 后重新归一化；论文公式写成与 0/1 mask 相乘，存在歧义。
* Table 2 的 SAG PSNR 正文/表格不一致，应使用表中 31.21 dB；不要把 31.12 当作复现目标。
* 单视图对象旋转会由生成先验补纹理；对 logo、包装背面等严格身份属性，优先使用多视图参考。
* 粗 mask 可用，但至少覆盖原 HOI 区域；过大 mask 会增加背景和人体被改写的范围。
* 公平比较应统一编辑首帧、输入分辨率、帧数、采样器、随机种子数量和评价视频集合。

### 7.4 是否可以迁移到其他任务

可以。Head-Sliding 的核心思想适用于任何“静态参考 token 需要持续影响长时序 token”的任务，例如人物身份一致的视频生成、Ego-Exo 跨视角参考注入、长程动作条件、机器人示范中的对象外观条件和多镜头视频编辑。HMG + SFG 适用于已知有效区域的条件生成，例如局部服饰替换、工具使用、面部区域编辑或具身任务中的交互区域建模。

迁移时需要满足两个条件：能够获得较可靠的时空区域 mask，且参考条件可以编码为 token。若目标任务的交互区域会动态扩张、mask 不可靠或条件需要双向融合，GenHOI 的单向 hard gate 可能过强，需要改为可学习稀疏路由、软掩码或不确定性感知门控。对 Ego-Exo 任务，可以把不同注意力头的“时间滑动”扩展为“时间 + 视角滑动”，但必须通过对齐误差、跨视角遮挡和因果时序实验验证，不能直接假设有效。

## 8. 总结

### 8.1 一句话概括

时空门控稳注入对象

### 8.2 速记版 Pipeline

1. 遮住源视频中的手-物区域，保留首帧和背景。
2. 把噪声、背景视频、掩码和对象照片编码成 token。
3. 让不同注意力头在不同时间位置读取对象照片。
4. 只允许对象信息流向手-物区域，并自适应调节强度。
5. 去噪生成跨帧对象一致、交互自然的视频。
