## 2. 摘要

### 2.1 摘要原文

To serve as a scalable data source for embodied AI, world models should act as true simulators that infer interaction dynamics strictly from user actions, rather than mere conditional video generators relying on privileged future object states. In this context, egocentric Human–Object Interaction (HOI) world models are critical for predicting physically grounded first-person rollouts. However, building such models is profoundly challenging due to rapid head motions, severe occlusions, and high-DoF hand articulations that abruptly alter contact topologies. Consequently, existing approaches often circumvent these physics challenges by resorting to conditional video generation with access to known future object trajectories. We introduce EgoHOI, an egocentric HOI world model that breaks away from this shortcut to simulate photorealistic, contact-consistent interactions from action signals alone. To ensure physical accuracy without future-state inputs, EgoHOI distills geometric and kinematic priors from 3D estimates into physics-informed embeddings. These embeddings regularize the egocentric rollouts toward physically valid dynamics. Experiments on the HOT3D dataset demonstrate consistent gains over strong baselines, and ablations validate the effectiveness of our physics-informed design.

### 2.2 摘要翻译

为成为具身人工智能可扩展的数据来源，世界模型应当充当真正的模拟器，严格依据用户动作推断交互动力学，而不应仅仅依靠特权性的未来物体状态进行条件视频生成。

在这一背景下，第一人称人—物交互（HOI）世界模型对于预测具有物理依据的第一视角展开序列至关重要。

然而，快速的头部运动、严重的遮挡，以及会突然改变接触拓扑的高自由度手部关节运动，使构建此类模型极具挑战。

因此，现有方法往往借助已知未来物体轨迹开展条件视频生成，从而回避这些物理挑战。

我们提出 EgoHOI，一种第一人称 HOI 世界模型，摆脱上述捷径，仅根据动作信号模拟具有照片真实感且接触一致的交互。

为在不输入未来状态的情况下确保物理准确性，EgoHOI 将三维估计中的几何和运动学先验提炼为物理信息嵌入。

这些嵌入对第一人称展开序列施加正则引导，使其趋向物理有效的动力学。

HOT3D 数据集上的实验表明，该方法相较强基线获得一致提升，消融实验验证了这一物理信息设计的有效性。

摘要来源：`sec/0_abstract.tex` 的完整正文，与 PDF p.1 Abstract 规范空白和换行断词后逐字一致。这里忠实翻译作者的物理性主张；对其证据强度的判断见 6.8。

## 3. 方法动机

### 3.1 作者为什么提出这个方法？

设想戴着第一人称相机拿起杯子：手指弯曲、杯子移动、相机随头部转动，三种变化同时出现在图像里。遮挡时，模型还必须记住杯子的形状和位置。具身学习希望利用这种生成视频训练或评估操作模型，因此只生成漂亮的下一帧并不足够，动作变化应引起相应的交互结果。

作者希望在不给定未来物体轨迹时，根据手部和相机控制生成可信视频。三维手结构能约束关节形态，相机几何能约束视角变化，首帧物体外观能帮助保持实体。论文选择把这些可解释先验注入已有视频扩散模型，利用其外观生成能力，同时补充交互中的结构约束。（Introduction，pp.1–3）

### 3.2 现有方法的痛点或不足是什么？

第一，许多 HOI 合成方法在固定第三人称视角研究，难以直接处理头戴相机带来的运动与遮挡。第二，若提前输入物体未来轨迹，模型在训练和推理时已经知道物体应该去哪里，无法检验从动作推断物体演化的能力。第三，普通视频模型主要学习 RGB 统计，容易出现手消失、指节畸变、相机漂移和物体纹理变化。

Wan、Cosmos 与 Uni3C 的对比呈现这些问题，但各方法使用的条件信息也有差别。附录 C.2 为文本条件基线生成视频描述，EgoHOI 获得稠密手轨迹和相机控制。因而主表同时反映结构化控制和模型设计的收益，不能把全部差距归因于某一个 adapter。（Related Works；§4.2；附录 C.2）

### 3.3 论文的核心假设或直觉是什么？

将“手怎样动”“相机怎样动”“物体最初长什么样”分别编码成与视频 latent 对齐的特征，就能减少生成过程的歧义。手部动作、相机轨迹和外观锚点提供互补信息，视频骨干学习剩余的物体响应及图像演化。

这里 physics-informed 指**几何与运动学归纳偏置**。论文没有展示显式接触求解器、质量/摩擦参数、守恒约束或物理残差损失。将其解释为“有物理结构引导的视频世界模型”较符合已报告机制。（§3.3–3.4）

## 4. 方法设计

### 4.1 整体 Pipeline

先补充三个背景概念：VAE 将 RGB 压缩为低分辨率 latent 并负责解码；DiT 在 latent token 上反复去噪生成视频；adapter 是向预训练网络注入新条件的小型可训练分支，LoRA 则以低秩参数更新适配大模型。

1. **准备控制与初始观察。** 读取首帧 RGB、81 帧手网格渲染、相机内外参和首帧物体分割外观。HOT3D 实验主要从带标定与三维标注的数据构建控制，论文关于从野外视频估计先验的动机不能视为已完成同等规模验证。
2. **生成三个条件流。** HKE 用三维卷积处理手渲染序列，并用独立二维卷积分支编码首帧手；EME 将相机轨迹转换为逐像素六维射线场，再提取时空特征；OEE 用冻结 VAE 编码首帧物体外观。
3. **对齐 token。** 手和相机特征对齐主视频 latent 的时间与空间网格，token 隐藏维为 5120。HKE 用门控残差加入主 token；EME 经零初始化线性层逐层注入；OEE 带偏移 RoPE 追加为注意力的 key/value 上下文。
4. **保留初始场景。** 首帧 VAE latent 与首帧手特征结合，再与噪声 latent 通道拼接；首帧 CLIP 特征向 cross-attention 提供全局图像参考。首帧路径和 OEE 分别强调全局场景与物体局部身份。
5. **训练并生成。** 基于 Wan 2.1 14B，训练条件分支及 LoRA，基础生成权重保留。论文预备部分给出扩散去噪损失；推理进行 50 步去噪，最后由 VAE 输出 81 帧 RGB。

**时间概念必须分开：** 扩散迭代的时间步表示噪声强度；视频帧索引表示真实运动时间。论文 Eq.6 给出递推世界模型表达，而 §3.4 的具体实现描述对整段视频 token 联合去噪。不能据递推记号断言代码采用逐帧在线自回归，也不能由 EME 内部的 causal convolution 推导整个模型严格在线因果。（Fig.2 p.5；§3 pp.4–9；附录 B pp.20–23）

### 4.2 关键模块

#### 模块 1：手部运动学嵌入 HKE

* 模块输入：逐帧手网格投影的渲染图，形状为 B×81×480×480×3，以及首帧手图。HOT3D 中使用 MANO 手网格和标定相机，渲染为与 RGB 像素对齐的灰度手形并以三通道输入。
* 模块处理过程：时序分支使用 Conv3d 与 SiLU；附录表 B.1 共列七层，前三层保持分辨率，随后逐步下采样，最后以核 (1,2,2)、步长 (1,2,2) 将 16 通道投影到 5120。参考分支用六层 3×3 Conv2d，通道依次 3→16→16→16→16→16→20，后三层 stride=2。前者保留整段手形变化，后者将初始手配置送入首帧 latent。
* 模块输出：与主 token 网格对齐的手特征，以及首帧低分辨率参考特征。5120 是 DiT token 隐藏宽度；20 是文中参考手分支的输出通道，二者含义不同。
* 模块作用：直接提供手指、掌面与运动轮廓，让生成过程维持关节结构和手的可见性。（§3.3 p.7；附录 B.1 pp.20–21）
* 为什么需要该模块：稠密图像表示能保留投影轮廓与像素对应关系；单个低维动作向量更难直接约束复杂手形。
* 如果没有该模块会怎样：表3的 Base 缺失率为 28.77%，单加 HKE 降至 6.47%，说明该分支对手部重建可靠性有较强作用；这是一项加法消融，不能等价于从完整模型移除 HKE 的结果。

#### 模块 2：自运动嵌入 EME

* 模块输入：整段相机内参 K、相对首帧的旋转/平移，以及各像素位置。构成 B×6×81×480×480 的逐像素射线场。
* 模块处理过程：先构造 Plücker 六维表示；三层因果三维卷积结合 GroupNorm、SiLU，步长为 (2,2,2)、(2,2,2)、(1,2,2)，得到 B×64×21×60×60。再经过通道 64/128/256 的混合时空阶段：二维残差卷积处理空间，沿 21 帧做时域自注意力；最后投影并 patchify。论文声明最终 token 网格为 21×30×30、隐藏维 5120；空间下采样的具体连接需结合代码核验，不能仅依文字自行补足。
* 模块输出：EME 几何 token，经 zero linear 注入前 D 个 DiT block。对额外 OEE token 所占长度补零；D 的具体值在所读正文和附录中未明确给出。
* 模块作用：将头部运动转换为图像位置对应的几何条件，减少转头、平移导致的视角漂移。（§3.3–3.4 pp.7–8；附录 B.2 pp.21–22）
* 为什么需要该模块：同一手部位移可以来自手自身运动或相机运动，显式相机条件帮助消除这种混淆。
* 如果没有该模块会怎样：表4中 Base 的 ATE 为 0.133，单加 EME 为 0.096，完整模型为 0.084；该证据支持 EME 对视角一致性的贡献，未直接证明接触动力学正确。

#### 模块 3：物体实体嵌入 OEE

* 模块输入：首帧分割得到的物体 RGB 外观。应保留前景颜色与纹理；只输入二值掩码无法提供论文所说的物体外观锚点。
* 模块处理过程：物体图缩放至 480×480、归一化到 [-1,1]，经冻结 Wan VAE，再以 (1,2,2) 三维卷积 patchify 为 5120 维 token；token 使用偏移 RoPE，作为额外参考流参与注意力的 key/value，主 token 从中检索物体特征。
* 模块输出：持续可访问的物体参考 token；它们自身不解码成视频。附录将单帧输入 B×3×1×H×W 写为编码后 B×16×21×60×60，缺少时间扩展操作的说明，复现时需查代码，不能假定单帧 VAE 自然产生 21 帧。
* 模块作用：在遮挡和视角变化后维持物体颜色、纹理与身份，降低实体漂移。（§3.3–3.4 pp.7–8；附录 B.3 pp.22–23）
* 为什么需要该模块：全局首帧 CLIP 特征对小物体局部细节约束有限；单独保留物体外观可减少背景干扰。
* 如果没有该模块会怎样：表5中 Base Object-CLIP 为 0.81，单加 OEE 为 0.83，完整模型为 0.92。OEE 单独带来适度收益，联合模型提升更大；还需完整的组合消融才能严格归因协同作用。

#### 模块 4：首帧锚定、条件融合与低秩适配

* 模块输入：首帧 RGB、首帧手特征、主噪声 latent、HKE/EME/OEE token。
* 模块处理过程：首帧 VAE 表示加入参考手特征，再与噪声沿通道拼接并 patchify；CLIP 首帧特征经线性投影进入 cross-attention。HKE 在输入 token 残差相加，EME 经零初始化投影逐层相加，OEE 提供 KV-only 参考；LoRA rank/alpha 均为 128。冻结骨干的说法指基础权重，LoRA 及新增条件模块仍可训练。
* 模块输出：经条件引导的去噪视频 latent，解码为交互 RGB 序列。
* 模块作用：保留预训练模型的外观生成先验，将几何条件稳定引入同一 token 空间。（§3.4 pp.8–9）
* 为什么需要该模块：新条件在训练初期可能扰乱已有生成能力，zero linear 的初始输出为零，使相机分支逐步学会调制；外观参考则维持初始场景。
* 如果没有该模块会怎样：从设计逻辑推断会削弱初始外观与新控制的兼容性；论文没有分别移除首帧 CLIP、reference-hand、zero initialization 或 LoRA 的数值消融，不能给出独立提升值。参考手 20 通道与正文首帧 VAE 表示相加的通道对齐操作也需代码确认。

### 4.3 关键公式或算法

#### 公式 1：世界模型状态与动作控制

* 完整公式：$$x_{t+1}=f_\theta(x_t,a_t),\qquad o_t\sim g_\phi(x_t),\qquad x_1=e_\phi(o_1),\qquad z_{t+1}=f_\theta(z_t,\mathbf H^t,\mathbf C^t),\quad t=1,\ldots,L.$$
* 变量含义：x 为抽象状态，o 为可观察图像，a 为动作；e/g 为编码/解码器；z 为 VAE latent，H 为手控制，C 为相机控制；θ/φ 为模型参数。
* 公式中每个部分的含义：先编码初始观察，再依据控制更新状态，再解码观察；最后一式将通用动作具体化为手与头运动。
* 公式整体的含义：描述在指定控制序列下生成未来观察的任务接口。（正文 Eq.1、2、6，pp.4–6）
* 公式目的：明确生成条件与预测目标，排除未来物体状态作为输入。
* 在方法流程中的作用：规定输入输出和 latent 动力学的概念框架，未完整指定实际视频扩散采样算法。
* 通俗理解：告诉模型手和头怎样动，让它预测眼前场景怎样变化；该记号本身不能证明网络学到可解释物理状态。

#### 公式 2：扩散加噪与去噪训练

* 完整公式：$$q(z_t\mid z_{t-1})=\mathcal N\!\left(z_t;\sqrt{1-\beta_t}\,z_{t-1},\beta_t\mathbf I\right),\quad t=1,\ldots,T;\qquad \alpha_t=1-\beta_t,\quad\bar\alpha_t=\prod_{s=1}^{t}\alpha_s.$$ $$z_t=\sqrt{\bar\alpha_t}\,z_0+\sqrt{1-\bar\alpha_t}\,\varepsilon,\qquad\varepsilon\sim\mathcal N(0,\mathbf I).$$ $$\mathcal L=\mathbb E_{z_0,\varepsilon,t}\left[\left\|\varepsilon-\varepsilon_\theta(z_t,t)\right\|_2^2\right].$$
* 变量含义：此处 t 为扩散步；z0 为干净视频 latent，zt 为含噪 latent；β 控制单步噪声方差，ᾱ 为累积信号保留量，ε 为已知采样噪声，εθ 为网络预测噪声。
* 公式中每个部分的含义：第一行定义逐步加噪分布；第二行直接采样某噪声级别；最后最小化预测噪声与真实噪声的平方误差。
* 公式整体的含义：通过从扰动数据中恢复结构，训练一个迭代视频去噪器。（正文 Eq.3–5，pp.5–6）
* 公式目的：建立生成视频的基本学习目标；正文该式为预备知识形式，未显式写出所有条件变量，也未给出独立物理损失项。
* 在方法流程中的作用：HKE/EME/OEE 通过条件融合影响去噪；物理引导主要进入表示结构，不能据此额外编造接触损失。
* 通俗理解：模型练习从不同程度的“雪花噪声”恢复符合手、相机和外观条件的视频。此处噪声步与公式1的视频帧时间使用相同字母，应按语境区分。

#### 公式 3：相机射线与 Plücker 表示

* 完整公式：$$\mathbf d_{u,v}=\mathbf R\mathbf K^{-1}\begin{bmatrix}u\\v\\1\end{bmatrix}+\mathbf t,\qquad\mathbf p_{u,v}=(\mathbf o\times\mathbf d_{u,v},\mathbf d_{u,v})\in\mathbb R^6.$$
* 变量含义：K 为内参，R/t 为相对首帧外参，u/v 为像素坐标，o 为文中定义的光心，d 为文中称作世界方向的向量，p 为六维射线表示。
* 公式中每个部分的含义：逆内参将像素反投影，旋转/平移转换到共同参考；叉积项描述射线的位置相关量，后一项描述方向相关量。
* 公式整体的含义：给每个像素附上与相机姿态关联的几何描述，形成图像对齐控制。（正文 Eq.7 p.7；附录 Eq.1 p.22）
* 公式目的：将相机轨迹变为具有空间分辨率的控制，支持视角一致的视频生成。
* 在方法流程中的作用：构造 EME 的六通道输入。**保留原式并标记疑点：** 标准几何中纯方向向量通常不加平移；若先求世界点，应减去光心再定义射线方向。论文未充分说明这里的约定；Plücker moment 也会随原点平移而变换，因此“对原点选择不变”的文字需谨慎解释。复现应核对官方 camera 实现。
* 通俗理解：把“相机向哪里看、怎样移动”写在每一个像素上。上述几何疑点属于原文定义问题，不能擅自修改原公式后声称是论文公式。

#### 公式 4：HKE 门控残差

* 完整公式：$$\mathbf X_0=\mathbf T_{\mathrm{main}}+\gamma_h\mathbf T^{\mathrm{HKE}}.$$
* 变量含义：Tmain 为视频主 token，THKE 为形状相同的手 token，γh 为可学习门控，X0 为融合结果；token 形状 B×N×d，d=5120。
* 公式中每个部分的含义：基础视频内容保留为残差主路径；门控调节手特征注入强度。
* 公式整体的含义：将手运动直接加入对应的视频 token。（正文 Eq.8 p.8）
* 公式目的：使细粒度手结构影响生成，同时保留骨干表示。
* 在方法流程中的作用：位于 DiT 主流输入端；参考手分支另在 patchify 前处理，不能与该式混为一条路径。
* 通俗理解：在视频特征上叠加可调强度的“手势提示”。论文没有在此规定 γh 的初始化值，不能自动认定为零。

#### 公式 5：EME 逐层零初始化适配

* 完整公式：$$\Delta\mathbf X_l=\mathbf U_l\!\left(\mathbf T^{\mathrm{EME}}\right),\qquad\mathbf U_l:\mathbb R^d\rightarrow\mathbb R^d,\quad l\text{ 位于前 }D\text{ 个 DiT blocks}.$$
* 变量含义：TEME 为相机 token，Ul 为第 l 层零初始化线性 adapter，ΔXl 为加入该层输入的残差。
* 公式中每个部分的含义：共享相机信息由各层独立投影；补零使 EME 长度适配含 OEE 的扩展序列。
* 公式整体的含义：在多个深度以残差方式引入相机几何。（正文 Eq.9 p.8）
* 公式目的：训练开始时新分支不改变原模型输出，随后学习适当的几何调制。
* 在方法流程中的作用：持续约束 DiT 内部视角演化；具体注入层数 D 未在文字中明确。
* 通俗理解：先让新增相机旋钮处于“零影响”，再逐步学会如何转动。

#### 公式 6：OEE 参考 token 拼接

* 完整公式：$$\mathbf T_{\mathrm{all}}=[\mathbf X_0;\mathbf T^{\mathrm{OEE}}].$$
* 变量含义：分号表示沿序列维拼接，X0 为动作融合后主 token，TOEE 为首帧物体参考 token，Tall 为扩展序列。
* 公式中每个部分的含义：主序列负责生成；追加序列以 shifted RoPE 定位为独立参考，提供注意力 key/value。
* 公式整体的含义：让生成中的视频持续访问首帧物体外观。（正文 Eq.10 p.8）
* 公式目的：减少遮挡后物体纹理和身份漂移。
* 在方法流程中的作用：OEE 在每个 DiT block 充当 KV-only context，只解码主 token。拼接公式本身没有表达全部注意力掩码/更新细节，应与文字共同理解。
* 通俗理解：随身携带一张物体参考照片，后续生成随时查阅。

#### 公式 7：物体二维位置与朝向误差

* 完整公式：$$c_x=\frac1A\sum_{i=1}^{A}x_i,\quad c_y=\frac1A\sum_{i=1}^{A}y_i,\quad e_{\mathrm{pos},t}=\frac{\sqrt{(c_x^{\mathrm{gt}}-c_x^{\mathrm{gen}})^2+(c_y^{\mathrm{gt}}-c_y^{\mathrm{gen}})^2}}{\sqrt{H^2+W^2}}.$$ $$\mu_{20}=\frac1A\sum_i(x_i-c_x)^2,\quad\mu_{02}=\frac1A\sum_i(y_i-c_y)^2,\quad\mu_{11}=\frac1A\sum_i(x_i-c_x)(y_i-c_y),\quad\theta=\frac12\operatorname{atan2}(2\mu_{11},\mu_{20}-\mu_{02}).$$ $$\alpha=\frac{\lambda_1-\lambda_2}{\lambda_1+\lambda_2+10^{-12}},\quad\delta_t=|\theta_t^{\mathrm{gt}}-\theta_t^{\mathrm{gen}}|\bmod\pi,\quad\Delta\theta_t=\min(\delta_t,\pi-\delta_t),\quad e_{\mathrm{ori},t}=\Delta\theta_t\frac{180}{\pi}.$$
* 变量含义：A 是掩码前景像素数，c 是质心，H/W 是图像尺寸；μ 是中心矩，λ1/λ2 是协方差特征值；θ 是主轴方向，α 为各向异性。
* 公式中每个部分的含义：OPE 用质心距离除图像对角线；OOE 用掩码主轴差，按 π 周期折叠到 0–90 度，再转换为角度。
* 公式整体的含义：分别测量物体在二维画面中的位置偏差和主轴朝向偏差。（附录 D.4 pp.26–27；δ 是为分行解释引入的中间记号，与原式等价）
* 公式目的：补充 CLIP 外观相似度无法直接衡量的几何误差。
* 在方法流程中的作用：用于评价而非训练；双空掩码 OPE=0，单空惩罚=1。OOE 仅使用 A≥20 且 α≥0.15 的有效帧，各 clip 后再作数据集宏平均；论文称同时报告有效帧比例，但所读结果表未给出该数值。
* 通俗理解：检查物体有没有出现在正确位置、长轴方向是否接近。二维形状主轴无法区分绕轴旋转或完整三维姿态，也会受遮挡与分割质量影响。

#### 公式 8：手部缺失率与分割误差

* 完整公式：$$\mathcal H=\{(t,i)\mid\text{hand }i\text{ is annotated at frame }t\},\quad v_{t,i}=\begin{cases}1,&\text{HaMeR gives a valid reconstruction},\\0,&\text{otherwise},\end{cases}\quad\mathrm{MR}=1-\frac1{|\mathcal H|}\sum_{(t,i)\in\mathcal H}v_{t,i}.$$ $$\mathrm{RMSE}_{\mathrm{seg}}=\sqrt{\frac1{T|\Omega|}\sum_{t=1}^{T}\sum_{x\in\Omega}\left(M_t(x)-\widehat M_t(x)\right)^2}.$$
* 变量含义：H 为真实手实例集合，v 为重建有效指示量，T 为评价帧数，Ω 为像素域，M/预测 M 为参考/生成图像分割得到的手臂掩码。
* 公式中每个部分的含义：MR 统计有效手重建的缺失比例；RMSE 将逐像素掩码差平方后平均开根。
* 公式整体的含义：衡量手是否持续可重建，以及可见手臂区域是否匹配。（附录 D.6–D.7 pp.27–29）
* 公式目的：识别完全消失和手臂空间范围缓慢漂移两种失败。
* 在方法流程中的作用：作为手部评估指标，与 MPJPE 互补。有效性要求高置信度且 MPJPE 有界，但阈值未明确报告；RMSE 按附录明确定义为掩码误差，正文把它与 RGB appearance 联系起来的表述不能改变其数学定义。
* 通俗理解：先查手有没有被可靠检测到，再查它占据的像素区域是否正确。HaMeR/SAM 的估计误差会进入评估结果。

## 5. 与现有方法对比

本质差异在于控制表示与融合位置：EgoHOI 将手部和相机轨迹变成稠密、图像对齐的结构条件，并持续保留首帧物体参考。它仍依靠大型视频扩散骨干学习图像演化。表中前三类为实际基线，其余为论文相关工作中的任务层面对照，不能当作主实验直接胜出记录。

| 方法 | 核心思想 | 优点 | 缺点 | 改进点 |
|---|---|---|---|---|
| Wan 2.1 | 首帧/文本条件视频生成骨干 | 具备大规模预训练外观先验 | 本协议下手形、视角和物体易漂移 | EgoHOI 在其上加入三类结构嵌入及 LoRA |
| Cosmos 2B/14B | 通用世界模型，经同数据后训练 | 模型规模和通用生成能力较强 | 本数据上的动作与接触细节约束有限 | 稠密手/相机条件及物体锚点提供针对性约束 |
| Uni3C | 相机和人体运动可控的视频生成 | 显式控制相机与人体运动 | 本实验中 MR=20.50%、ATE=0.168 | 专门表示高自由度手形与实体参考 |
| 未来物体轨迹条件 HOI（任务对照） | 已知物体后续位姿，再合成交互 | 指定目标轨迹的可控性强 | 不能单独检验从动作预测物体响应 | EgoHOI 去掉未来物体轨迹输入，仍保留未来手/头控制 |
| EgoExo-Gen（任务对照） | 从第三人称视频生成第一人称视频 | 利用另一视角观测 | 输入包含外部视角，任务接口不同 | EgoHOI 面向首帧与动作条件展开；未报告二者定量比较 |

## 6. 实验表现与优势

### 6.1 实验设置

Wan 2.1 14B 官方权重；LoRA rank=128、alpha=128；Adam、学习率 10^-5、BF16、CFG=1.0；8000 steps，16 张 NVIDIA H100，batch size=1，约训练一天。论文未清晰交代 batch size 是每卡还是全局。分辨率 480×480，训练/推理均 81 帧，推理去噪 50 步。（§4.1 p.9）

论文称模拟达到 16 FPS，但没有足够的端到端测时协议、运行硬件和单样本延迟说明；数据本身也以 16 FPS 构建。81 帧按 16 FPS 的播放长度约为 5 秒，不能据此认定 50 步扩散可实时交互运行。

### 6.2 数据集

HOT3D-Clips 提供第一人称 RGB、相机标定、手关节/网格和关联扫描模型的物体 6DoF 位姿。采用 Aria 前向 RGB 流 `214-1/camera-rgb`，150 帧一段、16 FPS；手渲染从 MANO 标注经同相机投影生成。虽然数据含未来物体位姿，方法条件声明不使用它。（附录 C.1 pp.23–24）

**需要保留的数据划分疑点：** 正文 §4.1 写从训练排除的场景挑选 100 clips；附录写以 clip 为单位随机 90%/10% 划分、1364 train/152 test。二者可能对应不同层次的评估集合，但论文没有给出明确映射。clip 不共享帧也不自动保证场景/物体独立，当前证据不足以确认严格跨场景泛化。

训练以 81 帧窗口、stride=5 在线抽取；一个 150 帧 clip 如完整滑窗可产生 14 个起点。窗口高度重叠，不能将每个窗口当作独立场景。正文仅说明测试也做 81 帧滑窗，未清晰给出最终测试窗口数与聚合细节。文本条件基线的描述由 Tarsier2-7B 对完整 150 帧片段采样关键帧生成，再用于对应各子窗口。（附录 C.2）

### 6.3 Baseline

Wan、Cosmos 2B、Cosmos 14B、Uni3C。论文明确 Wan/Cosmos 从发布权重按相同数据与协议微调；Uni3C 进入同一评估流程，但正文对其训练条件的展开较少。PlayerOne 等方法在投稿时因实现不可得未比较，阅读时不能据此推断当前仍不可得。（§4.2 pp.10–11）

“相同首帧”不等于“全部控制条件相同”：文本基线与 EgoHOI 的控制粒度不同。更严格的结构归因应看同骨干消融，并补充相同手/相机条件、相近训练参数量的 adapter 对照。

### 6.4 评价指标

* **逐帧质量：** PSNR/SSIM 越高越接近参考，LPIPS 越低越好；Object-CLIP 衡量物体外观特征余弦相似度，使用 open_clip ViT-B/32、LAION-2B S/34B，逐帧后平均。特征相似不能保证接触正确。
* **相机一致性：** ATE/RRE/RPE 越低越好。附录实际对真实和生成视频都运行 MapAnything，再对齐估计轨迹比较；因而属于重建器介导的参考轨迹一致性，并非直接以传感器真值检验所有物理状态。表中长度/对齐尺度等单位未完整明确，不擅自换算为厘米。
* **手运动学：** HaMeR 对真实和生成帧做重建，报告 MR、MPJPE、分割 RMSE，均越低越好。MR 的检测有效阈值、MPJPE 单位/对齐细节未完整给出；0.014 应保留原数值，不能直接宣布为 14 mm。
* **物体几何：** OPE 是图像对角线归一化质心差，OOE 是有效掩码二维主轴角误差（度），公式见4.3。它们均不等价于三维 6DoF 误差。
* **视频感知：** VBench 包含主体一致性、背景一致性、运动平滑度、动态程度、美学、成像质量。动态程度描述运动大小，须结合参考动作判断；其余维度较高通常更好，均不直接测量摩擦/碰撞。（附录 D pp.24–30）

### 6.8 局限性

**作者明确承认：** 附录 F p.32 指出完整评估物理合理性仍是开放问题，需要更直接的接触与动力学评价。现有结果主要依赖感知、重建器和二维几何指标。

**由材料可确认的边界：**

1. 没有显式质量、摩擦、力、接触约束求解，也没有量化穿透、无接触运动或碰撞响应。物体响应可由数据统计学得，其物理有效性尚未被充分检验。
2. 给定整段手与相机运动控制。去掉未来物体状态仍保留丰富的未来控制信息；实验主要基于 HOT3D 三维标注，野外估计误差、动作不可达性和分布外控制未充分量化。
3. 约5秒的81帧联合生成，未证明长时间闭环控制、错误恢复、在线交互或用于规划的收益。Introduction 的 VLA/机器人应用是动机，本文没有相应下游增益实验。
4. 数据划分 100 clips/152 test、场景独立性存在未解释关系；滑窗相关性、重复训练和不确定性报告不足。
5. MapAnything/HaMeR/SAM 使指标受估计器偏差影响；OOE 排除无效帧且未在结果表提供有效比例，可能隐藏困难样本。
6. 几何 Eq.7、OEE 单帧到21帧、参考手20通道融合、EME空间网格说明均有待代码核实的细节；这些原文问题不改变已报告表格，但影响复现。
7. 16 H100 的训练成本较高，推理延迟信息不足；公开推理代码的存在不等于完整训练与权重均可一键复现。

## 7. 学习与应用

### 7.1 是否开源

2026-10-14 核验：官方仓库公开，包含 `infer.py`、`egohoi/{camera,dataset,inference,model}.py`、随附 `diffsynth` 和依赖清单。README 说明需自行提供 Wan DiT、text encoder、VAE、image encoder 与 EgoHOI checkpoint，数据也不包含在仓库中。所读 README 的权重段落没有可核验下载链接，不能宣称权重齐备；页面未见完整训练入口说明。[官方代码](https://github.com/phai-lab/EgoHOI)

项目页有方法图、基线视频和代码入口，可用于汇报时辅助观看。[项目主页](https://egohoi.github.io/)

### 7.2 复现关键步骤

1. 获取有合法使用权限的 HOT3D-Clips 和 Wan 2.1 14B 相关模型，先确认 EgoHOI checkpoint 可获得；当前阅读任务仅核查条件，没有执行训练。
2. 选择 RGB `214-1`，按相机标定渲染 MANO 手网格，准备首帧物体 RGB 掩码、相机轨迹。先完成 clip/scene 划分再取滑窗，并保存实际 clip ID 清单，以消除原文划分歧义。
3. 检查控制图与 RGB 时间对齐，按81帧、480×480构建窗口。官方推理目录包含 `videos/`、`saved_pose/`、`obj_mask/`、`camera_traj1/`；先用单 clip 验证读取和形状。
4. 对照 `camera.py` 与 `model.py` 核实射线坐标约定、物体时间扩展、参考手通道融合、EME 注入层数及 KV-only 实现；这些步骤必须先于重新训练。
5. 如具备完整训练实现和权重，按 rank/alpha=128、学习率10^-5、BF16、8000 steps复现；论文给出的配置不能替代缺少的训练脚本与具体参数。
6. 推理设81帧、480×480和50步，固定随机种子；用相同 MapAnything、HaMeR、SAM、CLIP 与评估窗口复算指标，再核对主表和消融。

### 7.3 需要注意的实现细节

**输入语义：** 手渲染提供运动与轮廓，物体分割提供首帧外观；不能把未来物体掩码作为输入，否则改变论文任务。相机内参应随 resize/crop 正确缩放，手网格与相机必须共用坐标和时间基准。

**形状与位置编码：** 视频81帧压缩到 latent 时间21，空间480到60再patchify到30；d=5120。参考 token 使用 shifted RoPE；需要保持视频位置与参考位置语义区分。按论文声明每路21×30×30即18900 tokens，追加参考会增加注意力负担，不能用“轻量 adapter”推断整体推理开销很小。

**训练与评价：** 冻结基础模型同时训练 LoRA，需分清参数组。MR 的阈值、MPJPE 单位与对齐、OOE 有效帧比例均应明确保存。主表 Wan 与消融 Base 不直接等价；正文中的 RGB appearance 描述不能替代附录的掩码 RMSE 定义。

**版本边界：** 官方仓库示例输出 FPS=24，而论文 HOT3D 数据为16 FPS；输出容器帧率与预测控制的时间刻度应分别设定。当前发布代码可能晚于 v1，若代码行为与 v1 不同应记录，不自动将新实现写回 v1 方法。

### 7.4 是否可以迁移到其他任务

对 Ego-Exo 研究可考虑用外部视角提升手运动估计，再向第一人称生成器提供手/相机结构条件；这是可检验的研究设想，论文没有验证跨视角融合。应同时评估外参误差和遮挡下手形估计误差，避免把额外视角信息的收益全部归因于融合机制。

对 VLA 与机器人学习，可探索用受控生成补充视觉训练数据，或将 OEE 作为对象记忆参考。必须新增策略成功率、动作一致性、接触/穿透和跨物体测试；人手渲染与机器人末端执行器的结构不同，不能直接假定零样本迁移。对于规划，还需验证不同动作候选的结果能否可靠排序，而不仅是生成可观看的视频。

## 8. 总结

### 8.1 一句话概括

用三维先验引导手物视频生成

### 8.2 速记版 Pipeline

1. 看首帧，确定场景与物体外观。
2. 提供手怎样动、相机怎样动。
3. 将手形、相机几何与物体参考送入视频模型。
4. 反复去噪，生成交互视频。
5. 检查手形、视角与物体是否稳定；物理正确性仍需直接验证。
