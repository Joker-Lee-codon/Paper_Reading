## 2. 摘要

### 2.1 摘要原文

Generating realistic hand-object interactions (HOI) videos is a significant challenge due to the difficulty of modeling physical constraints (e.g., contact and occlusion between hands and manipulated objects). Current methods utilize HOI representation as an auxiliary generative objective to guide video synthesis. However, there is a dilemma between 2D and 3D representations that cannot simultaneously guarantee scalability and interaction fidelity. To address this limitation, we propose a structure and contact-aware representation that captures hand-object contact, hand-object occlusion, and holistic structure context without 3D annotations. This interaction-oriented and scalable supervision signal enables the model to learn fine-grained interaction physics and generalize to open-world scenarios. To fully exploit the proposed representation, we introduce a joint-generation paradigm with a share-and-specialization strategy that generates interaction-oriented representations and videos. Extensive experiments demonstrate that our method outperforms state-of-the-art methods on two real-world datasets in generating physics-realistic and temporally coherent HOI videos. Furthermore, our approach exhibits strong generalization to challenging open-world scenarios, highlighting the benefit of our scalable design. Our project page is <https://hgzn258.github.io/SCAR/>.

### 2.2 摘要翻译

由于物理约束（例如手与被操作物体之间的接触和遮挡）难以建模，生成逼真的手物交互（HOI）视频是一项重大挑战。现有方法使用 HOI 表征作为辅助生成目标来指导视频合成。然而，二维与三维表征之间存在两难：二者无法同时保证可扩展性与交互保真度。为解决这一限制，我们提出一种结构与接触感知表征，它无需三维标注即可捕获手物接触、手物遮挡以及整体结构上下文。这一面向交互且可扩展的监督信号，使模型能够学习细粒度交互物理规律，并泛化到开放世界场景。为了充分利用所提出的表征，我们引入一种采用共享与专门化策略的联合生成范式，同时生成面向交互的表征和视频。大量实验表明，在生成符合物理规律且时间连贯的 HOI 视频方面，我们的方法在两个真实世界数据集上优于现有最先进方法。此外，我们的方法在具有挑战性的开放世界场景中展现出很强的泛化能力，突出了其可扩展设计的优势。项目主页为 <https://hgzn258.github.io/SCAR/>。

## 3. 方法动机

### 3.1 作者为什么提出这个方法？

通用图像到视频模型能够生成视觉上较为逼真的画面，但 HOI 视频要求模型理解“哪个手正在接触哪个物体、手和物体谁遮挡谁、物体处于什么相对深度、操作后物体应如何运动”。这些约束只靠 RGB 重建目标很难稳定学到，因而会出现手指或物体形变、手悬空、错误抓取、物体突然消失或生成动作不符合文本等问题。作者希望给视频扩散模型增加一种能够明确暴露交互结构的辅助监督，使模型在学习外观的同时学习接触与空间关系。

作者的第二个动机是扩展监督规模。高保真的三维手网格、物体网格或动作捕捉数据能表达结构，但采集成本高，难以覆盖 10 万级真实视频和开放词汇物体；光流、二维关键点或分割掩码容易大规模提取，却各自缺少整体深度、显式接触或足够的结构信息。SCAR 试图用可自动提取的二维轮廓、接触代理和视频深度图，在“规模”与“交互信息量”之间取得更实用的平衡。

### 3.2 现有方法的痛点或不足是什么？

第一，通用 I2V 模型缺少针对 HOI 的归纳偏置。即使画面纹理自然，也可能没有正确执行文本动作，或在接触瞬间破坏手、工具和目标物体的几何关系。

第二，现有 HOI 表征存在可扩展性—保真度冲突。光流强调运动，却不直接表示接触和场景深度；手物分割强调位置，却不提供整体三维结构；二维关键点只覆盖稀疏手部骨架；三维网格更完整，但依赖昂贵的三维标注，而且接触语义仍可能需要额外构造。

第三，许多方法采用“先预测中间表征，再以该表征生成视频”的两阶段流程。训练第二阶段时常使用真实中间表征，而推理时只能使用第一阶段的预测，形成训练—推理分布差异。第一阶段的噪声、目标漂移或缺失会被第二阶段放大，造成误差累积。SCAR 因而不把 HOI 表征当成推理时必须先生成好的硬条件，而是让 RGB 与 HOI 表征在同一去噪器内互相作用并同步生成。

### 3.3 论文的核心假设或直觉是什么？

核心直觉有两层。其一，**接触增强轮廓负责“在哪里交互”，深度图负责“场景结构是什么”**；两者叠加后，信息比单一二维信号完整，又不需要真实三维网格。其二，RGB 视频与 HOI 表征描述的是同一次交互，因此早期网络层应共享空间布局和时间动力学等语义，后期网络层则应分别恢复 RGB 外观和结构化表征的专属细节。由此得到“先共享、后专门化”的分层联合去噪器。

这里需要区分作者主张与证据边界：联合生成和消融结果支持这种辅助表征有助于提高所选视频指标与定性质量，但论文没有直接证明模型学得了完整、可外推的真实物理定律。更稳妥的说法是，模型学到了对所评测 HOI 视频更有用的结构与接触统计规律。

## 4. 方法设计

### 4.1 整体 Pipeline

1. **离线构造监督表征。** 对训练 RGB 视频与任务文本，CoT 提示的 Qwen2.5-VL 先定位参与交互的手和物体，SAM2 再从框提示生成并传播逐帧掩码；人工检查和修正自动掩码。随后从掩码提取手轮廓与物体轮廓，通过轮廓膨胀后的交集估计接触区域，并用视频一致深度估计器生成逐帧相对深度图。接触增强轮廓最终通过 alpha blending 覆盖在深度图上，得到 $V_{\mathrm{HOI}}$。
2. **编码两种视频模态。** 冻结的 3D VAE 分别把 RGB 视频 $V_{\mathrm{RGB}}$ 与视频形态的 HOI 表征 $V_{\mathrm{HOI}}$ 编码为视觉 token $X_{\mathrm{RGB}}$ 和交互 token $X_{\mathrm{HOI}}$，再拼接成统一序列 $Z=X_{\mathrm{RGB}}\oplus X_{\mathrm{HOI}}$。
3. **加入扩散噪声与条件。** 训练时对联合潜变量加噪得到 $Z_t$。观测图像被补齐未来空白帧后经 VAE 编码，形成图像条件 token；任务描述被文本编码器转为文本 token。它们共同条件化 DiT 去噪过程。
4. **共享语义去噪。** DiT 的前 $k^*$ 层同时处理两类 token。相同时间—空间位置的 RGB 与 HOI token 使用相同位置编码，并在第 $k^*$ 层用余弦距离对齐对应隐藏状态，迫使两条流共享布局、运动和交互语义。
5. **专门化细节去噪。** 从第 $k^*+1$ 层开始，只给交互 token 加可学习的 $d_{\mathrm{HOI}}$ 嵌入，使后续层能够区分 RGB 外观细节与 HOI 结构细节。对 Q/K/V 投影的 LoRA 更新也只在交互 token 位置激活，以复用预训练视觉知识并新增对 HOI 表征的适配能力。
6. **联合训练与联合解码。** 总损失同时包含 RGB 扩散损失、HOI 扩散损失和跨模态对齐损失。推理从联合高斯噪声 $Z_T$ 反向去噪到 $Z_0$，再把两部分 token 分别经 VAE 解码为 RGB 视频和同步 HOI 表征。

### 4.2 关键模块

#### 模块 1：结构与接触感知表征的数据构造

* 模块输入：训练视频、任务描述，以及视频各帧的 RGB 内容。
* 模块处理过程：CoT 引导的 VLM 结合文本意图、视觉交互线索与时间运动定位手和被操作物体；SAM2 生成并跨帧传播掩码；人工审核修正掩码。掩码边界被转为稀疏轮廓，手轮廓用固定半径膨胀，物体轮廓用随物体框对角线变化且被上下界截断的半径膨胀，两者交集作为接触区域。同时，视频深度模型估计跨帧一致的相对深度。轮廓和接触标记被 alpha blending 到深度图上。
* 模块输出：与 RGB 视频逐帧对齐的 $V_{\mathrm{HOI}}$，包含手物空间定位、接触代理、遮挡/相对深度与整体场景结构。
* 模块作用：把难以从 RGB 像素损失中直接获得的交互线索显式化，作为训练时的额外生成监督。
* 为什么需要该模块：只有光流、掩码或关键点时，模型容易缺少接触或深度；真实三维标注又难以扩展到超过 10 万条视频。该模块让监督既能大规模构造，又比单一二维信号更全面。
* 如果没有该模块会怎样：主文表 2 显示，用 OF、HOM 或 DM 单独替换完整表征时，五项指标均低于 SCAR；定性结果还出现物体消失、漏抓和接触不准。需要注意，这些结论是在 Taco 与 SCAR-C 设置下得到，不代表所有数据和骨干都必然相同。

#### 模块 2：统一潜空间与联合生成范式

* 模块输入：RGB 视频、对应 HOI 表征、观测首帧和任务文本。
* 模块处理过程：同一个 3D VAE 架构把两种“视频状”输入映射到兼容潜空间；两类 token 拼接后一起加噪、一起送入同一 DiT，并在一次反向扩散过程中共同恢复。
* 模块输出：相互同步的 RGB token 与 HOI token，随后解码为 $\hat V_{\mathrm{RGB}}$ 和 $\hat V_{\mathrm{HOI}}$。
* 模块作用：将 HOI 表征从两阶段系统中的外部预测条件，变成与视频同时学习、能够双向交换信息的辅助生成目标。
* 为什么需要该模块：两阶段方案会把第一阶段的错误固定下来并传给第二阶段；联合生成允许两种模态在多层注意力中共同修正。
* 如果没有该模块会怎样：补充材料表 S1 中，两阶段版本的 SC/IQ/ISC/IBC/VCS 为 0.893/0.676/0.943/0.947/0.182，而联合生成达到 0.916/0.698/0.951/0.954/0.187；定性图 S4 显示两阶段中间预测偏差会导致最终视频退化。

#### 模块 3：Shared Semantics 共享语义模块

* 模块输入：带噪视觉 token、带噪交互 token、文本条件、图像条件和扩散时间步；两类 token 在相同时间—空间位置共享位置编码。
* 模块处理过程：DiT 第 1 至第 $k^*$ 层联合建模两种模态，并在第 $k^*$ 层对每一对同位置隐藏状态计算余弦距离。最小化该距离使它们在空间布局、时间动态和交互事件上保持一致。
* 模块输出：语义耦合的视觉与交互隐藏状态。
* 模块作用：防止 RGB 流生成一种动作、HOI 流却描述另一种接触或结构，让辅助表征确实能约束视频流。
* 为什么需要该模块：仅拼接 token 并不保证模型会使用两者的对应关系；共享位置编码与显式对齐损失提供了结构性约束。
* 如果没有该模块会怎样：补充材料表 S2 的 specialization-only 版本为 0.908/0.689/0.944/0.956/0.184，整体低于 share-and-specialization 的 0.916/0.698/0.951/0.954/0.187，尤其 IQ、ISC 与 VCS 下降。不过 IBC 单项略高（0.956 对 0.954），说明该设计不是对每个指标都严格占优。

#### 模块 4：Specialized Details 专门化细节模块

* 模块输入：第 $k^*$ 层输出的两种模态隐藏状态。
* 模块处理过程：从第 $k^*+1$ 层开始，仅对交互 token 添加可学习交互嵌入 $d_{\mathrm{HOI}}$，打破早期强制共享形成的对称性；同时对注意力 Q/K/V 的 LoRA 残差使用二值掩码，只让交互 token 接收适配更新。
* 模块输出：能够分别恢复自然 RGB 外观和轮廓—深度 HOI 表征细节的隐藏状态。
* 模块作用：保留两种模态的共同语义后，再学习颜色纹理与结构标记之间的模态差异。
* 为什么需要该模块：若所有层都强制共享，两种输出可能难以分别恢复自己的统计特性；HOI 表征不应被当成普通 RGB 外观直接生成。
* 如果没有该模块会怎样：补充材料表 S2 的 share-only 版本降至 0.854/0.639/0.915/0.917/0.170，是三种策略中最差，支持“只共享、不分化”会显著损害生成。另一方面，过早或过晚切换也不理想：表 S3 显示 $k^*=12$ 的总体平衡优于 $4,20,32$ 层设置。

#### 模块 5：交互 token 专用 LoRA 适配

* 模块输入：每层经位置编码调制的联合序列 $P_k$ 和预训练 Q/K/V 投影矩阵。
* 模块处理过程：基础投影 $P_k\mathbf W_z$ 对全部 token 生效；低秩残差由 $\operatorname{diag}(\mathbf M)$ 屏蔽，只注入交互 token 位置。SCAR-C 使用 LoRA rank 128，SCAR-W 使用 rank 256。
* 模块输出：视觉 token 主要沿用预训练视频模型的投影，交互 token 获得额外可学习变换。
* 模块作用：以参数高效方式把现成 I2V 骨干扩展到新表征模态，同时降低对既有视觉生成能力的扰动。
* 为什么需要该模块：HOI token 分布与自然 RGB token 不同，完全冻结会缺乏适配能力；对全部 token 无差别更新又可能破坏预训练外观知识。
* 如果没有该模块会怎样：论文没有提供“去掉掩码 LoRA”或“全量微调 Q/K/V”的独立消融，因此无法把最终增益精确归因于该模块；现有证据只能确认它是完整系统的实现组成。

### 4.3 关键公式或算法

#### 公式 1：尺度自适应的物体轮廓膨胀半径

* 完整公式：$$r_{\mathrm{o}}=\min\left(r_{\max},\max\left(r_{\min},\beta\cdot L\right)\right).$$
* 变量含义：$L$ 是物体包围框对角线长度；$\beta$ 是比例系数；$r_{\min}$ 与 $r_{\max}$ 是半径下、上界；$r_{\mathrm{o}}$ 是物体轮廓膨胀半径。
* 公式中每个部分的含义：$\beta L$ 让半径随物体图像尺度变化；内层 $\max$ 防止小物体半径过小；外层 $\min$ 防止大物体半径无限增大。
* 公式整体的含义：在不同物体尺寸下，用受限的自适应像素邻域判断“边界足够接近”。
* 公式目的：提高接触代理对极小、极大物体尺度变化的鲁棒性。
* 在方法流程中的作用：它决定物体轮廓被膨胀的范围，并直接影响下一式得到的接触区域。
* 通俗理解：大物体允许更宽的“可能接触带”，小物体使用更窄的带，但二者都不会窄到漏检或宽到把大量非接触区域算进去。

#### 公式 2：手物接触区域代理

* 完整公式：$$C=\operatorname{dilate}(E_{\mathrm{hand}},r_{\mathrm{h}})\cap\operatorname{dilate}(E_{\mathrm{object}},r_{\mathrm{o}}).$$
* 变量含义：$E_{\mathrm{hand}}$、$E_{\mathrm{object}}$ 是手和物体的细轮廓；$r_{\mathrm h}$ 是固定手轮廓膨胀半径；$r_{\mathrm o}$ 是上一式的物体半径；$C$ 是估计接触区域。
* 公式中每个部分的含义：`dilate` 将一条细边界扩成邻域带；交集保留手边界邻域与物体边界邻域重叠的像素。
* 公式整体的含义：当手和物体边界在图像中足够接近时，把邻域重合处视为接触代理。
* 公式目的：在没有三维接触标注的情况下，以可扩展的二维几何操作生成接触监督。
* 在方法流程中的作用：$C$ 被编码到接触增强轮廓中，再与深度图融合成最终 HOI 表征。
* 通俗理解：把手和物体的边缘都“描粗”，两条粗边重叠的位置就标为可能接触处。它是近似代理，并不能排除透视投影中“看起来相邻、三维上未接触”的情况。

#### 公式 3：联合潜变量的前向扩散

* 完整公式：$$Z=X_{\mathrm{RGB}}\oplus X_{\mathrm{HOI}},\qquad Z_t=\sqrt{\bar\alpha_t}\,Z+\sqrt{1-\bar\alpha_t}\,\varepsilon.$$
* 变量含义：$\oplus$ 表示 token 序列拼接；$Z$ 是干净联合潜变量；$\bar\alpha_t$ 是累计噪声调度系数；$\varepsilon$ 是高斯噪声；$Z_t$ 是时间步 $t$ 的带噪潜变量。
* 公式中每个部分的含义：第一项保留按调度缩放的原始信号，第二项加入随时间增强的噪声。
* 公式整体的含义：RGB 与 HOI 两种潜变量被视为同一联合随机变量，一起经历扩散加噪。
* 公式目的：训练一个去噪器来学习两种输出的联合分布，而非两个串行条件分布。
* 在方法流程中的作用：它建立联合生成训练目标；推理时模型从 $Z_T$ 逐步恢复 $Z_0$。
* 通俗理解：先把“真实视频”和“它的交互结构图”捆成一组并一起打乱，模型学习同时把两者复原。

#### 公式 4：共享语义对齐损失

* 完整公式：$$L_{\mathrm{align}}=\sum_{m=1}^{S}\left(1-\frac{H_{k^*}^{m}\cdot H_{k^*}^{S+m}}{\lVert H_{k^*}^{m}\rVert\,\lVert H_{k^*}^{S+m}\rVert}\right).$$
* 变量含义：$S$ 是单一模态的 token 数；$H_{k^*}^{m}$ 是第 $k^*$ 层第 $m$ 个视觉 token 隐状态；$H_{k^*}^{S+m}$ 是同位置的交互 token 隐状态。
* 公式中每个部分的含义：分式是对应隐藏向量的余弦相似度；$1-$相似度是余弦距离；对所有同位置 token 求和得到整体对齐损失。
* 公式整体的含义：让两种模态在共享阶段结束时，对相同时间—空间位置形成相近的高层表示。
* 公式目的：显式传递共同的布局、运动与交互语义，减少两条生成流不一致。
* 在方法流程中的作用：它作用于第 $k^*$ 层，形成“共享”与“专门化”的层级分界。最终设置为 $k^*=12$、$\lambda_{\mathrm{align}}=0.1$。
* 通俗理解：同一帧同一位置的 RGB 内容与结构图应该讲同一件事；若两者隐藏向量方向差异很大，模型就会被惩罚。

#### 公式 5：共享时空位置编码

* 完整公式：$$P_k^m=\begin{cases}H_{k-1}^{m}+p^m,&m\le S,\\H_{k-1}^{m}+p^{m-S},&m>S.\end{cases}$$
* 变量含义：$H_{k-1}^{m}$ 是上一层第 $m$ 个隐藏状态；$p^m$ 是时空位置编码；$P_k^m$ 是进入第 $k$ 层自注意力前的调制 token。
* 公式中每个部分的含义：视觉序列使用 $p^m$；交互序列第 $m$ 个 token 使用与其对应视觉 token 相同的 $p^{m-S}$。
* 公式整体的含义：两种模态中代表同一帧、同一空间块的 token 拿到相同坐标标识。
* 公式目的：在网络结构层面显式告诉注意力机制哪些 RGB 与 HOI token 互相对应。
* 在方法流程中的作用：每个 DiT 层都利用该对应关系，配合第 $k^*$ 层的对齐损失建立跨模态耦合。
* 通俗理解：给两张同步地图上的同一格贴同一个坐标标签，模型更容易把它们配对。

#### 公式 6：交互 token 选择性 LoRA 更新

* 完整公式：$$\mathbf X_z^{\star}=P_k\mathbf W_z+\gamma\,\operatorname{diag}(\mathbf M)\operatorname{LoRA}_z(P_k),\qquad z\in\{\mathcal Q,\mathcal K,\mathcal V\}.$$
* 变量含义：$\mathbf W_z$ 是预训练注意力 Q/K/V 投影矩阵；$\operatorname{LoRA}_z$ 是低秩适配分支；$\gamma$ 是缩放系数；$\mathbf M\in\{0,1\}^{2S}$ 是只在交互 token 位置取 1 的二值掩码。
* 公式中每个部分的含义：$P_k\mathbf W_z$ 是全部 token 的基础投影；第二项是低秩残差；对角掩码把残差限制在 HOI token 位置。
* 公式整体的含义：RGB token 主要沿用预训练模型的注意力投影，HOI token 额外获得专门适配。
* 公式目的：参数高效地引入新模态能力，同时尽量保留原有视频生成知识。
* 在方法流程中的作用：它存在于共享和专门化两个模块的各个 DiT 层中，是交互 token 接入预训练骨干的底层机制。
* 通俗理解：保留原模型处理普通视频的主通路，只给新加入的“交互结构 token”安装小型可训练插件。

#### 公式 7：联合训练总目标

* 完整公式：$$L=L_{\mathrm{RGB}}+\lambda_{\mathrm{HOI}}L_{\mathrm{HOI}}+\lambda_{\mathrm{align}}L_{\mathrm{align}}.$$
* 变量含义：$L_{\mathrm{RGB}}$ 与 $L_{\mathrm{HOI}}$ 分别是 RGB、HOI token 的扩散预测损失；$L_{\mathrm{align}}$ 是跨模态隐藏状态对齐损失；$\lambda_{\mathrm{HOI}}$ 与 $\lambda_{\mathrm{align}}$ 是权重。
* 公式中每个部分的含义：第一项保证主 RGB 视频生成，第二项要求模型能生成辅助表征，第三项要求两种生成在共享语义层一致。
* 公式整体的含义：系统同时优化外观质量、交互结构可生成性和跨模态一致性。
* 公式目的：让 HOI 表征真正成为训练信号，并避免辅助任务与主任务相互脱节。
* 在方法流程中的作用：它端到端训练层级联合去噪器；实验中 $\lambda_{\mathrm{HOI}}=1.0$、$\lambda_{\mathrm{align}}=0.1$。
* 通俗理解：既要把视频还原好，也要把“接触与深度草图”还原好，还要确保两者讲的是同一次动作。

## 5. 与现有方法对比

SCAR 的本质区别不只是换了一个控制信号，而是同时改变了**辅助表征的内容**和**使用辅助表征的方式**。相对于通用 I2V，它增加结构与接触监督；相对于光流、分割或关键点，它组合了定位、接触代理和相对深度；相对于真实三维网格，它牺牲绝对三维精度以换取可扩展构造；相对于两阶段方法，它把中间表征从先验条件改为与 RGB 同步生成的辅助目标。论文实验直接比较了 CogVideoX、Wan2.1 与 FLOVD；下表中 3D 网格类的优缺点来自论文动机与相关工作分析，不应误读成表 1 的直接数值比较。

| 方法 | 核心思想 | 优点 | 缺点 | 改进点 |
|---|---|---|---|---|
| CogVideoX / Wan2.1 通用 I2V | 由首帧与文本直接生成视频 | 预训练规模大，外观生成能力强 | 缺少 HOI 专用接触与结构偏置，可能动作错误、手物形变或接触不实 | 增加可生成的 HOI 辅助模态，用结构与接触监督约束主视频 |
| FLOVD 两阶段方法 | 先预测光流，再以预测光流条件化视频生成 | 显式建模运动，流程清晰 | 光流不表达接触与深度；第一阶段误差会固定并传入第二阶段 | RGB 与 HOI 表征联合去噪，通过互相修正缓解误差累积 |
| 手物分割或轮廓 | 显式表示手和物体的位置 | 易提取、可扩展 | 单独使用时缺少深度；普通掩码没有显式接触 | 稀疏轮廓保留底层深度图，并把边界邻近区域编码为接触代理 |
| 2D 手关键点 | 用稀疏骨架表示手部动作 | 标注或检测成本相对低 | 难覆盖物体结构、掌面接触与遮挡；额外复杂目标可能妨碍优化 | 使用手物轮廓、接触区与深度的互补组合；表 2 中额外加入关键点反而下降 |
| 3D 网格 / 点云类 HOI 表征 | 明确建模手和物体三维几何 | 结构信息完整，适合精细几何控制 | 三维采集和标注昂贵，难扩展到开放世界大规模视频 | 用单目视频深度和二维几何代理提供相对结构，无需真实 3D 标注 |
| SCAR | 接触增强轮廓 + 深度图；RGB 与 HOI 联合生成；先共享后专门化 | 兼顾规模、结构、接触和端到端生成，在两个数据集及自建开放世界集上指标领先 | 接触仍是二维代理；需要多模型数据处理与人工审核；指标未直接测量真实物理 | 论文目标方法 |

## 6. 实验表现与优势

### 6.1 实验设置

作者将方法分别接入 CogVideoX-I2V-5B 与 Wan2.1-I2V-14B，得到 SCAR-C 和 SCAR-W。两种实现保留基础模型原 VAE 潜空间、DiT 层数和隐藏维度。Taste-Rob 生成长度为 17 帧，Taco 为 25 帧。两种模型都在第 12 层应用对齐损失；LoRA rank 分别为 128 与 256；$\lambda_{\mathrm{HOI}}=1.0$，$\lambda_{\mathrm{align}}=0.1$。

公平性方面，通用骨干和基线均在相同数据划分上微调，并从相同预训练检查点初始化。FLOVD 使用基于 CogVideoX 的实现而非 SVD 实现，以便与 SCAR-C 更可比。补充材料进一步说明训练使用 8 张 NVIDIA A100 80GB，AdamW、学习率 $10^{-5}$；CogVideoX 系列训练 5 个 epoch、batch size 64，Wan2.1 系列训练 3 个 epoch、batch size 16；推理均采用 50 个采样步和 classifier-free guidance 6.0。

### 6.2 数据集

* **Taste-Rob：** 100,856 个固定视角真实 HOI 视频，每条带人工任务描述，包含单手和双手交互以及 grasping、lifting、rotating 等多种动作、物体和场景布局。论文沿用 Taste-Rob 原划分。它更接近机器人/固定相机交互，并非纯人类第一视角数据。
* **Taco：** 2,317 个双手交互视频，含第一与第三视角；论文只使用第一视角视频。作者按 `(action, tool, target object)` 三元组类别做 90%/10% 随机训练—测试划分。
* **开放世界基准：** 作者另收集 200 个困难样本，每个样本含任务描述和包含未见目标物体的图像；用在 Taste-Rob 上训练的 SCAR-W 测试。补充材料表 S4 报告这一集合的量化结果。该基准规模较小，且论文未给出其公开下载、采样协议或独立标注者质量控制细节。

### 6.3 Baseline

主实验比较三类基线：通用 I2V 骨干 CogVideoX、Wan2.1，以及先生成光流再生成视频的两阶段方法 FLOVD。表示消融还比较 Optical Flow（OF）、Hand-Object Masks（HOM）和 Depth Maps（DM），以及去掉手物轮廓（w/o HOC）、去掉接触区域（w/o CG）、去掉深度（w/o DM）、加入二维手关键点（+KP）的变体。补充材料比较两阶段与联合生成范式，以及 specialization-only、share-only 和完整 share-and-specialization 策略。

### 6.4 评价指标

所有主指标来自 VBench，越高越好：

* **SC（Subject Consistency）：** 视频主体跨帧一致性。
* **IQ（Imaging Quality）：** 单帧成像质量。
* **ISC（I2V Subject Consistency）：** 生成视频主体与观测图像的对应一致性。
* **IBC（I2V Background Consistency）：** 生成背景与观测图像的一致性。
* **VCS（ViCLIP Score）：** 文本任务与视频语义对齐程度。
* **TS（Total Score）：** 按 VBench 系数组合上述维度的加权总分。

这些指标能衡量视觉、条件保持和文本对齐，却没有直接测量接触力、穿模率、物体轨迹守恒、动作成功率或真实三维碰撞，因此“physics-realistic”仍部分依赖定性观察与间接指标。

### 6.5 主实验结果

主文表 1 的完整结果如下：

| 数据集 | 方法 | SC | IQ | ISC | IBC | VCS | TS |
|---|---|---:|---:|---:|---:|---:|---:|
| Taste-Rob | CogVideoX | 0.959 | 0.688 | 0.955 | 0.954 | 0.187 | 8.959 |
| Taste-Rob | Wan2.1 | 0.943 | 0.700 | 0.947 | 0.939 | 0.185 | 8.897 |
| Taste-Rob | FLOVD | 0.941 | 0.691 | 0.949 | 0.956 | 0.189 | 8.888 |
| Taste-Rob | SCAR-C | **0.964** | 0.696 | 0.960 | **0.959** | 0.193 | 9.043 |
| Taste-Rob | SCAR-W | 0.961 | **0.709** | **0.961** | 0.958 | **0.194** | **9.084** |
| Taco | CogVideoX | 0.895 | 0.665 | 0.933 | 0.942 | 0.182 | 8.511 |
| Taco | Wan2.1 | 0.905 | 0.717 | 0.933 | 0.947 | 0.189 | 8.792 |
| Taco | FLOVD | 0.903 | 0.686 | 0.927 | 0.947 | 0.177 | 8.619 |
| Taco | SCAR-C | **0.916** | 0.698 | **0.951** | **0.954** | 0.187 | 8.793 |
| Taco | SCAR-W | 0.912 | **0.728** | 0.948 | 0.952 | **0.191** | **8.899** |

在 Taste-Rob 上，SCAR-W 相对其 Wan2.1 骨干的 TS 从 8.897 升至 9.084，绝对提高 0.187；IQ、ISC、IBC、VCS 分别提高 0.009、0.014、0.019、0.009。SCAR-C 相对 CogVideoX 的 TS 提高 0.084，并在 SC、ISC、IBC、VCS 上上升，但 IQ 从 0.688 到 0.696 的提升较小。

在 Taco 上，SCAR-W 相对 Wan2.1 的 TS 提高 0.107，IQ 从 0.717 到 0.728，ISC 从 0.933 到 0.948，IBC 从 0.947 到 0.952，VCS 从 0.189 到 0.191。SCAR-C 相对 CogVideoX 的 TS 从 8.511 提高至 8.793；相对 FLOVD，其 ISC 从 0.927 提高到 0.951，符合作者关于两阶段方法更容易丢失物体身份的解释。值得注意的是，SCAR-C 在两个数据集的 IQ 均不如 Wan2.1，说明方法优势主要体现在综合一致性与条件遵循，而非每个单项都压倒所有不同规模骨干。

开放世界补充表 S4 中，SCAR 的 SC/IQ/ISC/IBC/VCS 为 0.907/0.730/0.927/0.931/0.256；CogVideoX 为 0.909/0.709/0.921/0.929/0.239，Wan2.1 为 0.892/0.719/0.911/0.921/0.234，FLOVD 为 0.903/0.711/0.916/0.924/0.238。SCAR 在 IQ、ISC、IBC、VCS 上最高，但 SC 0.907 略低于 CogVideoX 的 0.909，因此“跨所有指标优于基线”的文字表述与表 S4 的 SC 单项并不完全一致，应以表中数值为准。

### 6.6 消融实验

主文表 2 在 Taco、SCAR-C 设置下比较 HOI 表征：

| HOI 表征 | SC | IQ | ISC | IBC | VCS |
|---|---:|---:|---:|---:|---:|
| OF | 0.889 | 0.660 | 0.935 | 0.942 | 0.177 |
| HOM | 0.903 | 0.689 | 0.939 | 0.945 | 0.181 |
| DM | 0.889 | 0.682 | 0.940 | 0.944 | 0.180 |
| w/o HOC | 0.899 | 0.689 | 0.937 | 0.945 | 0.181 |
| w/o CG | 0.906 | 0.687 | 0.945 | 0.948 | 0.179 |
| w/o DM | 0.901 | 0.690 | 0.939 | 0.941 | 0.180 |
| + KP | 0.891 | 0.691 | 0.940 | 0.943 | 0.183 |
| SCAR | **0.916** | **0.698** | **0.951** | **0.954** | **0.187** |

完整 SCAR 对所有替代表征与删减变体均在五项指标上最好。去掉轮廓、接触区域或深度都会退化，支持三种信息互补。`+ KP` 没有继续提升，作者解释为过于复杂的辅助生成目标使优化更难；该解释合理，但论文没有提供训练损失曲线或优化诊断来直接证明因果机制。

补充材料进一步验证：

* **联合生成对两阶段：** 0.916/0.698/0.951/0.954/0.187 对 0.893/0.676/0.943/0.947/0.182，支持缓解误差累积。
* **共享—专门化策略：** 完整策略总体优于 specialization-only（0.908/0.689/0.944/0.956/0.184）与 share-only（0.854/0.639/0.915/0.917/0.170）；但 specialization-only 的 IBC 0.956 略高于完整模型 0.954。
* **对齐层位置：** 在 $\lambda_{\mathrm{align}}=0.1$ 时，$k^*=12$ 给出 0.916/0.698/0.951/0.954/0.187；$k^*=4,20,32$ 的总体表现更弱。过早对齐可能语义尚未形成，过晚对齐可能干扰模态细节。
* **对齐权重：** 固定 $k^*=12$ 时，$\lambda_{\mathrm{align}}=0.1$ 的整体平衡好于 0.01 和 0.5；但不同指标并非全部单调，显示对齐强度需要折中。

### 6.7 可视化或定性结果

主文图 4 的 Taco 例子要求“Use the eraser to brush the bowl”。CogVideoX 出现手部/接触失真，Wan2.1 没有正确执行 brushing，FLOVD 出现由光流误差传播导致的物体幻觉；SCAR-C 与 SCAR-W 保持目标物体并完成更连贯的刷动。图 5 显示 FLOVD 光流噪声较大，而 SCAR 同步生成的深度—轮廓表征在时间上更一致。

主文图 6 的开放世界例子要求把橙色胡萝卜玩具放入半透明玻璃杯。CogVideoX 把物体送向绿色碗，Wan2.1 选错对象，FLOVD 只把胡萝卜移向杯子，SCAR 则更完整地执行“into”的关系。补充图还展示了笔记本移到粉色杯旁、红色火腿放入锅中等案例，支持 SCAR 对目标物体与动作关系的保持能力。

定性证据仍有两点边界：静态帧网格难以完整呈现视频时间连贯性，作者也提示应查看补充视频；示例由作者挑选，论文没有报告盲评者人数、偏好比例或失败案例分布。因此这些图能说明典型行为，但不能独立估计总体成功率。

### 6.8 局限性

论文没有单列 limitations，以下边界来自方法、实验和开放资源的综合核对：

1. **二维接触代理不等于真实接触。** 轮廓膨胀交集只表示投影平面上边界接近，可能把遮挡、相邻或深度分离误认为接触，也不能表达接触力、法向或穿模程度。
2. **深度只有相对结构。** 单目视频深度本身尺度不确定；作者利用的是相对深度排序，因此模型并未得到可度量的真实三维几何。
3. **数据构造仍非完全自动。** VLM grounding、SAM2 和深度估计都可能出错，作者还需要人工审核并修正掩码。10 万级处理的人工成本、接受率和残余标注误差没有量化。
4. **评测不直接等价于物理真实性。** VBench 指标主要评价视频质量、首帧一致性和文本对齐，没有物理接触、动作完成、物体状态保持或三维碰撞指标，也没有用户研究。
5. **开放世界证据有限。** 自建集只有 200 个样本，且由在 Taste-Rob 上训练的 SCAR-W 评测；数据是否公开、类别覆盖、采样和人工评价协议没有充分说明。其表 S4 中 SCAR 的 SC 还略低于 CogVideoX。
6. **时长和任务复杂度有限。** 主实验只生成 17 或 25 帧，未展示长时程多步骤任务、交互结束后的长期状态稳定性，或闭环机器人控制效果。
7. **数据划分可能不足以检验组合泛化。** Taco 是在每个 `(action, tool, target)` 三元组类别内部随机做 90/10 划分，而不是严格把某些组合整体留出；因此主测试更偏分布内泛化，开放世界能力主要由另一个小基准支撑。
8. **完整代码复现条件不足。** 当前仓库明确发布了处理后的 TASTE-Rob 表征，但现有 README 未提供完整训练/推理代码、权重、所有数据处理参数（如 $\beta,r_{\min},r_{\max},r_h$）或开放世界基准下载。
9. **计算成本较高。** 方法依赖 5B/14B 视频模型、双模态联合 token 和大规模预处理；补充材料使用 8 张 A100 80GB。联合序列也会增加注意力和显存成本，论文未报告与基础骨干的训练/推理时间及显存增量。

## 7. 学习与应用

### 7.1 是否开源

项目主页、论文 PDF、官方 arXiv LaTeX 源码和 GitHub 仓库可访问。仓库在 2026-03-16 发布了 TASTE-Rob 上处理后的 Structure and Contact-aware Representation 数据链接；截至 2026-09-27，现有 README 未确认完整模型训练代码、推理代码或权重已发布。因此可以研究表征数据和论文实现细节，但尚不能把它视为开箱即用的完整官方复现仓库。

### 7.2 复现关键步骤

1. 准备 Taste-Rob 或 Taco 视频、任务文本和与论文一致的数据划分；Taco 只保留第一视角。
2. 用 CoT 引导的 Qwen2.5-VL 从文本和视频中定位交互手与目标物体，再用 SAM2 传播逐帧掩码，并建立人工审核流程。
3. 从掩码提取轮廓，设置 $r_h,\beta,r_{\min},r_{\max}$，用膨胀轮廓交集得到接触代理；用一致视频深度模型生成相对深度，并将接触增强轮廓 alpha blend 到深度图。
4. 选择 CogVideoX-I2V-5B 或 Wan2.1-I2V-14B，复用其 3D VAE 与 DiT，把 RGB 和 HOI 视频编码为长度匹配的 token 序列。
5. 实现共享位置编码、在第 12 层的余弦对齐损失、后半段交互嵌入，以及仅作用于交互 token 的 Q/K/V LoRA 掩码更新。
6. 使用联合扩散目标训练；先复现基础骨干和 FLOVD 公平设置，再逐项加入表征、联合生成、共享/专门化以验证增益来源。
7. 在 VBench 指标之外，建议增加接触正确率、穿模率、动作完成率、目标物体选择准确率、终态保持和人工盲评，使“物理真实性”有更直接证据。

### 7.3 需要注意的实现细节

* 稀疏轮廓而非稠密掩码是有意设计：稠密掩码 alpha blending 后会遮蔽底层深度，削弱整体结构信息。
* $r_o$ 必须随物体尺度自适应且做上下界裁剪；固定物体膨胀半径会对大小物体产生系统性偏差。论文没有公开所有具体半径值，复现时需要通过验证集选择并记录。
* RGB 与 HOI token 必须有一一对应的时间—空间排列，才能共享位置编码并计算式 4 的逐位置对齐损失。
* 对齐层和权重不可简单设得越深或越大越好。补充实验显示 $k^*=12$、$\lambda_{\mathrm{align}}=0.1$ 是折中；过晚或过强会妨碍专门化和主去噪任务。
* 交互嵌入应从 $k^*+1$ 层开始且只加到 HOI token；LoRA 二值掩码也必须与拼接后的 token 索引严格对应。
* 两类 VAE 潜变量的尺度、归一化与噪声调度要一致，否则对齐损失可能主要反映数值尺度而非语义。
* 复现实验应保留同一数据划分、初始化和微调预算。SCAR-C 与 SCAR-W 参数规模不同，不能只比较最终分数就把差异全部归因于表征。
* 数据处理链中 VLM、SAM2、深度模型和人工审核都可能引入版本差异，应保存中间掩码、接触图、深度图和质检记录。

### 7.4 是否可以迁移到其他任务

可以，但最有价值的不是直接复制“轮廓颜色图”，而是迁移三条设计原则。第一，把难以从主输出直接学到的交互约束做成可大规模生成的辅助模态；例如机器人操作可用末端执行器—物体接触、深度、分割和运动轨迹，Ego-Exo 可用跨视角对应与可见性图。第二，让辅助模态与主模态联合生成而非串行预测，降低中间条件误差的不可逆传播。第三，在网络深度上先对齐共享语义，再分化模态细节，适合 RGB—深度、视频—动作、Ego—Exo 等“强相关但统计形式不同”的多模态组合。

迁移时需要重新验证表征是否真的包含目标任务所需信息。例如把 SCAR 用于闭环机器人策略时，还需动作、力、状态转移和长时终态监督；把它用于 Ego-Exo 融合时，需要处理视角间非像素对齐，不能直接套用“同位置 token 共享位置编码”的假设。

## 8. 总结

### 8.1 一句话概括

结构接触表征约束交互生成

### 8.2 速记版 Pipeline

1. 从训练视频提取手、物体、接触区域和相对深度。
2. 把轮廓与深度融合成可扩展的交互结构视频。
3. 将 RGB 视频和交互结构编码到统一潜空间并共同去噪。
4. 网络前半段对齐共同语义，后半段分别恢复两种模态细节。
5. 从首帧与文本同时生成交互视频和同步结构表征。
